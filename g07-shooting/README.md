# g07 シューティング

自機を左右に動かして弾を撃ち、上に並んだ 18 個の的を全部落とす CLI ゲームです。
撃てる弾は同時に 3 発まで。全部落とすとタイムと命中率が出ます。

g01〜g06 は関数だけで書いてきましたが、この課題から `class` を使います。
自機・弾・的という**それぞれ位置を持つ物体**が同時に何個も動くので、
「データとそれを動かす手続き」を 1 つにまとめる書き方が要る、というのが今回の動機です。

この課題はスペースインベーダーへの 3 段階の 1 段目です（g08 で敵の編隊、g09 で反撃とバリア）。

## ブラウザ版

インストールせずに遊べます → **https://hicocho.github.io/python-study/g07/**

ソースは [`docs/g07/game.py`](../docs/g07/game.py)。`Ship` / `Bullet` / `Target` の 3 クラスと
`make_targets()` / `collide()` を、ステップの目印コメント（`# ←`）を除いて 1 文字も変えずに持ってきています。
持ってこなかったのは `render()` と `draw()`、`read_key()` とメインループだけ。
つまり違うのは**入口と出口**で、キーボードの生読み取りがキーイベントに、
文字の盤面が 252 個の `<div>` に入れ替わっています。
当たり判定も弾の進み方も 1 つも書き直していません。

## 仕様

- 画面は 21 × 12。的は上から 2 行目と 4 行目に 1 マスおき、計 18 個
- 的は動かない。撃たれると消える
- 弾は 0.08 秒ごとに 1 段上がる。当たるか画面の外に出ると消える
- 弾 1 発が消せる的は 1 個まで
- 画面に同時に出せる弾は 3 発まで。撃ち終わるまで次が撃てない
- 的を 18 個すべて落とすとクリア。タイム・撃った数・命中率が出る
- `q` で中断すると、残り数と命中率が出る

## メモ

### なぜここでクラスなのか

g05 のオセロも g06 のマインスイーパも、盤という 1 つの入れ物があって、
関数が外からそれを書き換える形でした。今回はそれが通りません。

弾は撃つたびに増え、当たるたびに減ります。1 発 1 発が自分の座標を持ち、
それぞれ勝手に上へ進む。**同じ種類の物体が、いくつあるか分からないまま同時に存在する**。
これを盤の書き換えで表すと、「どのマスの `|` が何番目に撃った弾か」を別に管理することになります。

クラスにすると、物体 1 つがそのまま変数 1 つになります。

```python
class Bullet:
    def __init__(self, x, y):
        self.x = x
        self.y = y
        self.mark = "|"

    def update(self):
        self.y -= 1
```

`Bullet(10, 10)` と呼ぶと Python が空のオブジェクトを作り、それを `self` として
`__init__` に渡します。`self.x = x` は「今できたこのオブジェクトに `x` という名前で値をしまう」。
`bullet.x` で取り出せるのは、そこにしまったからです。

`bullet.update()` は Python が `Bullet.update(bullet, ...)` に読み替えます。
**呼ぶときは書かないのに定義には書く**のが `self` で、「`.` の左側が `self` に入る」と覚えると迷いません。

### 型が違っても、形が同じなら同じように扱える

`Ship` `Bullet` `Target` は別々のクラスですが、3 つとも `x` `y` `mark` を持っています。
だから描画は種類を気にせず書けます。

```python
for target in targets:
    rows[target.y][target.x] = target.mark

for bullet in bullets:
    rows[bullet.y][bullet.x] = bullet.mark

rows[ship.y][ship.x] = ship.mark
```

当たり判定も同じで、`hits()` の引数を `target` ではなく `other` にしてあります。

```python
def hits(self, other):
    """相手と同じマスにいるなら True。"""
    return self.x == other.x and self.y == other.y
```

相手に `x` と `y` さえあれば動くので、g08 で敵が出てきても 1 文字も直りません。
**相手の型を決め打ちしない。**

`Target` に `update()` が無いのも同じ考え方です。的は動かないので進み方を持ちません。
3 つ揃えるために空のメソッドを書く必要はなく、**そのものが実際にできることだけを書けばいい**。

### 弾は自機に作らせる

弾の初期位置を計算しているのはメインループではなく、自機自身です。

```python
class Ship:
    def shoot(self):
        """自分の1つ上に弾を1発つくって返す。"""
        return Bullet(self.x, self.y - 1)
```

```python
bullets.append(ship.shoot())
```

砲口の位置を変えたくなったら `Ship.shoot` だけ直せば済み、メインループは自機の中身を知らずにいられます。
g08 で敵が撃ち返してくるとき、敵に同じ `shoot()` を持たせれば
`enemy_bullets.append(enemy.shoot())` と**まったく同じ形**で書けます。

### 消すのではなく、残すものを選ぶ

今回いちばん間違えやすいところです。「画面の外に出た弾を消す」をこう書くと動きません。

```python
for bullet in bullets:
    if not bullet.alive():
        bullets.remove(bullet)      # 危ない
```

`for` がリストを頭から見ている最中にそのリストから要素を抜くと、番号が 1 つ前にずれて
**次の要素が飛ばされます**。3 発並んで外に出たとき 2 発しか消えない、という気づきにくいバグです。

正しくは、古いリストを読みながら新しいリストを作り、最後に名前を付け替えます。

```python
bullets = [b for b in bullets if b.alive()]
```

読む対象と書く対象が別物なのでずれようがありません。
**「消す条件」ではなく「残す条件」を書く。**メソッド名を `alive()`（生きている）にしてあるのはそのためです。

`collide()` が `live_bullets = []` から組み立てているのも、`live_targets = list(targets)` と
複製してから削っているのも、同じ理由です。後者は「関数を呼んだら知らないうちに
引数のリストが変わっていた」を避けるためで、g04 の `place()` で `[row[:] for row in board]` と
複製したのと同じ形です。

### ループの中で消さない

`collide()` は的を見つけても、その場では消しません。

```python
for target in live_targets:
    if bullet.hits(target):
        hit = target
        break

if hit is None:
    live_bullets.append(bullet)
else:
    live_targets.remove(hit)
```

見つけた的を変数に覚えて `break` し、**`for` を抜けてから** `remove()` します。
1 つ前と同じ話で、走査中のリストをその場で削らないための形です。

`break` があるので 1 発の弾が消せる的は 1 個まで。的が重なっていない今は差が出ませんが、
g08 で敵が密集すると効いてきます。

### 数えずに、引き算で出す

命中数はカウンタを回して数えていません。

```python
return live_bullets, live_targets, len(targets) - len(live_targets)
```

`collide()` は最初と最後の的のリストを両方持っているので、**減った数がそのまま命中数**です。
数え忘れも二重カウントも起きません。カウンタを足す前に「差を取れば出ないか」と考えてみる。

### 上書きするから、桁を固定する

`draw()` は画面を消しません。`\x1b[H` でカーソルを左上に戻し、上から書き直しています。

```python
sys.stdout.write("\x1b[H" + frame)
sys.stdout.flush()
```

g04 は 0.8 秒に 1 回の更新でしたが、今回は毎秒 12 回以上書き換わります。
`\x1b[2J` で消してから `print` を 3 回すると、**消えた瞬間が目に見えてチラつく**。
消さずに上書きし、`write` を 1 回だけ呼ぶことでちらつきが止まります。

ただし上書きなので、行が短くなると前の文字が残ります。だから表示の桁を固定してあります。

```python
frame += f"\n残り {len(targets):2d} 個   弾 {len(bullets)}/{MAX_BULLETS}   {elapsed:5.1f} 秒"
```

`5.1f` は「小数点以下 1 桁、全体で 5 文字ぶんの幅」。`  0.4` も `123.9` も同じ長さになります。
g03 の `:.1f` に幅の指定が付いただけです。

### 描く順番が、重なりの上下になる

`render()` は 的 → 弾 → 自機 の順に書き込みます。後に書いたものが上に見えるので、
弾が的の上を通ると `*` ではなく `|` が見えます。
g08 でバリアや敵の弾が増えると、この順番がそのまま前後関係の設計になります。

### 0 で割らない

```python
accuracy = hits / shots * 100 if shots else 0.0
```

条件式（`値A if 条件 else 値B`）です。1 発も撃たずに `q` で抜けると `shots` が 0 になり、
そのまま割ると `ZeroDivisionError` で落ちます。`if shots` は「0 でなければ」の意味で、
g02 の `if not history:` と同じ「空・ゼロをそのまま条件にする」書き方です。

### 引数が増えてきた

```python
def draw(ship, bullets, targets, elapsed):
```

渡すものが 4 つになりました。g08 で「敵」「敵の弾」「バリア」「残機」が加わると手に負えなくなります。
そこが `class Game` の出番で、**ゲームの状態そのものを 1 つのオブジェクトにまとめる**ことになります。

ブラウザ版では一足先にその形になっていて、`state` という辞書に全部入れてあります。
キーイベントから何度も呼ばれるので、ループの中の素の変数では持てないからです。
辞書をクラスに変えれば、それが `class Game` です。
