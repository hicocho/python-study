## 今回の主題

**1. 波の形を差し替える — `TypeAlias` で「形」に名前を付ける**

g73 の `tone()` は `math.sin` を直に書いていた。ここでは「位相を受けて −1〜1 を返すもの」
という 1 つの型にそろえ、外から渡す。

```python
Shape: TypeAlias = Callable[[float], float]         # 位相（0〜1）を受けて −1〜1 を返すもの


def tone(note: int, seconds: float, wave_shape: Shape = sine) -> array:
    count = int(RATE * seconds)
    turn = pitch_hz(note) / RATE                    # 1 標本ぶんで進む位相
    samples = array("h")
    for i in range(count):
        samples.append(int(32767 * VOLUME * fade(i, count) * wave_shape(turn * i)))
    return samples
```

音色を足すのに `tone()` を書き直さなくてよくなる。`math.tau`（＝2π）を使うと、
波の式が「1 周ぶん進める」と読める。

**2. 倍音を重ねる — `functools.reduce`**

```python
HARMONICS = ((1, 1.0), (2, 0.5), (3, 0.25), (4, 0.125))     # 倍音とその強さ
LOUDEST = 1.3953                                    # 重ねたときの実際の山の高さ（測った値）


def organ(phase: float) -> float:
    return reduce(lambda total, part: total + part[1] * math.sin(math.tau * part[0] * phase),
                  HARMONICS, 0.0) / LOUDEST
```

`reduce` は「表を 1 つの値に畳む」道具。`for` で書いても同じだが、
**畳んでいることがそのまま形に出る**。

`LOUDEST` を「強さの合計（1.875）」にすると音が小さくなる。倍音は山の位置がずれているので、
**足した波の山は、山の高さの合計より低い**（実測 1.3953）。ここは測って決めた。

**3. 場所を決めて書き込む — `memoryview`**

```python
def melody(notes: list[tuple[int, int]], wave_shape: Shape = sine) -> array:
    counts = [int(RATE * length * BEAT) for _, length in notes]
    line = array("h", bytes(2 * sum(counts)))       # 2 バイト × 標本の数ぶんの空き地
    view = memoryview(line)
    for start, (note, length), count in zip(accumulate(counts, initial=0), notes, counts):
        view[start:start + count] = tone(note, length * BEAT, wave_shape)
    return line
```

`memoryview` は**中身を写さずに一部を指す**。先に全部ぶんの入れ物を作っておけば、
つなぐたびに配列を作り直さずに済む。始まる場所は `accumulate`（長さを順に足したもの）から出る。

## 遊び方

```
 白鍵  z x c v b n m   q w e r t y u i     ← 本物のピアノと同じ並び
 黒鍵   s d   g h j     2 3   5 6 7

 スペース  お題を聞く（クリアしたら次の曲へ）
 リターン  答え合わせ
 BS        最後に打ち込んだ音を 1 つ消す
 , .       いま打ち込んだ音の長さを短く／長く（ブラウザは矢印キーでも）
 Esc       やめる
```

画面は 128 × 80 ドット。上が音の並び、その下に**長さの帯**、いちばん下が鍵盤。

```
  ┌────────────────────────────┐
  │      ▬▬                    │  いま打ち込む場所
  │ ────────────────────────── │  半音ごとの目盛り
  │ ──■■──────────■■────────── │  ■ 青 = 決まった音　■ 橙 = 打ち込み中
  │ ──────■■──────────■■────── │
  │ ▬  ▬▬  ▬  ▬▬▬▬             │  長さの帯（長い音ほど帯が長い）
  ├────────────────────────────┤
  │ █▌█▌ ▌█▌█▌█▌ ▌█▌█▌ ▌█▌█▌█▌ │  25 鍵（2 オクターブ）
  └────────────────────────────┘
```

長さは**置いてから直す**。鍵を押して音を置き、長ければ `.`、短ければ `,`。
選び先は**その曲に出てくる長さだけ**（47 曲のうち 37 曲は 2 種類しかない）。

## 仕様

- 八分音符 = 0.19 秒。使う長さは 1・2・3・4・6・8（八分音符いくつぶんか）
- 音色 4 種。曲が進むと変わる（1〜12 サイン / 13〜24 三角 / 25〜36 オルガン / 37〜47 のこぎり）
- 確定は**高さと長さの両方**が合ったときだけ。片方だけ合っていても消える
- `--check` が見るもの: 波の形が −1〜1 に収まるか／倍音を重ねると急になるか／
  **`memoryview` で組んだ旋律が、素直につないだものと一致するか**／曲集／
  高さだけ・長さだけでは確定しないこと／**47 曲すべてが必ず解けるか**

## メモ

- **「音色が違う」を数字で見る。** 波の形の違いは「いちばん急な変わり方」に出る。
  サイン 0.0157 / 三角 0.0100 / オルガン 0.0366 / のこぎり 1.9950。
  最初は「合計の変化量」で測ったが、これは山の高さでほぼ決まってしまい、倍音の多さが出なかった
- **`LOUDEST` は合計ではなく実測。** 倍音の山はずれているので、足した波の山は合計より低い。
  合計で割ると音が小さくなる（実測 1.3953 に対して合計 1.875）
- **長さを横幅で見せると、どこを直せばいいのか分からなくなる。** 1 つ長さを間違えるだけで
  それより右の音が全部横にずれる。**位置は等分、長さは下の帯**に分けた
- **「いま打ち込む場所」の印は帯とぶつかった。** 最初はロールの下に置いたが、長さの帯と同じ行に
  なったので、ロールの**上**へ移した
- **長さの選び先を曲の中に絞った。** 6 種類から選ばせると、耳ではなく総当たりの作業になる
- 総当たりでの上限は 57 回（g73 は 13 回）。高さ 13 通り × 長さの種類ぶん。
  ただし人はリズムを先に聞き取れるので、実際にはここまでかからない
