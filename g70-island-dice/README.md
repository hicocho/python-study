# g70 アイランド・ダイス（サイコロで進む 3D ボードゲーム）

島をうねうね進む一本道（分かれ道つき）。サイコロを振ってコマを進め、止まったマスでお金が増えたり減ったり、カードを引いたり。
自分 ＋ CPU 3 人（性格が違う）。全員がゴールしたら所持金で順位。
**中身は Python、サイコロの物理は Cannon-es、絵は Three.js** の 3 層。端末は上から見た島の地図で、出目は乱数。

```
python3 main.py            # 遊ぶ（スペースで振る。分かれ道は 1（本道）か 2（近道）。q でやめる）
python3 main.py --check    # 決まりを確かめる
python3 main.py --sheet    # 遊んでいる場面（地図）を PNG に書き出す
```

ブラウザ版: https://hicocho.github.io/python-study/g70/ （画面の上で指をはらってサイコロを投げる。強さと向きが反映）

## 主題

- **マスは表と道の網**：`MAIN_LAYOUT = "S+.?-+.?…G"` の文字 1 つが 1 マス。`build_squares()` が制御点の道（Catmull-Rom → 等間隔）に沿って `Square` を置き、`next` で次のマスを指す。分かれ道は `next` が 2 つ（2 つ目が近道）。近道は本道の後ろに続く番号で、最後の `next` が合流先
- **手番の状態機械**：`ROLL`（振るのを待つ／CPU は 0.9 秒）→ `MOVING`（1 マス 0.28 秒で跳ぶ）→ 分岐に止まれば `FORK`（選ぶ）→ `EVENT`（出来事を見せる）→ `next_turn()`（ゴール済みと休みを飛ばす）。ゴールは超えても止まる
- **出目は外から渡す**：`world.roll(value)`。端末と検査は `roll_random()`、ブラウザは Cannon-es で転がったサイコロの上の面を読んで渡す。**CPU の番も同じサイコロが転がる**（Python の乱数を `wait_left = 1e9` で止めて、ブラウザが投げる）
- **地形は式**：`height(x, z)`（真ん中が高く縁で海へ、山 1 つ、うねり）。端末の地図も 3D の島も同じ式から。マスの高さもここから
- **性格つきの CPU**：`PERSONALITY` の表（近道を選ぶ確率。順位が下なら上がる）。堅実 15/35%、いじわる 40/70%、賭け 80/95%

## マスとカード

| 文字 | マス | 何が起きる |
|---|---|---|
| `+` | お金が増える | 300〜800（順に回す） |
| `-` | 減る | 200〜500 |
| `?` | カード | 9 種：給料日 +600、宝くじ +1200、財布 −500、税金（全員 −200）、おごり（1 位から +400）、追い風（3 進む）、迷子（2 戻る）、昼寝（休み）、全員に配る |
| `!` | 1 回休み | 次の手番を飛ばす |
| `$` | 宝 | 最初に着いた 1 人だけ +1500（本道と近道に 1 つずつ） |
| `G` | ゴール | 着いた順に +3000 / 2000 / 1000 / 500 |

## ブラウザ（Three.js ＋ Cannon-es）

| もの | 作り方 |
|---|---|
| 島 | `height()` を 72 × 72 の格子で読んで三角形の板に。色は `ground()`（海・砂・草・岩・雪）。水は半透明の板 |
| 道とマス | マスは円盤、道は帯（傾きも合わせる）。スタート・ゴール・宝には光る輪。木 70 本は草の上・道から離れた所に |
| コマ | 円錐＋球。同じマスなら 4 隅にずらす。跳ぶときは放物線。手番の人は回って輪が付く |
| サイコロ | `BoxGeometry` に canvas で描いた目 6 枚。**Cannon-es** の `Body`（箱）を石の台（床の `Plane` と 4 つの壁）に投げる。`velocity` は指のはらい、`angularVelocity` はでたらめ |
| 上の面を読む | 6 面の法線を `quaternion.vmult` で回し、y が一番大きい面の目。速さが 0.08 未満で 0.35 秒続いたら止まった。4.5 秒で時間切れ、落ちたら投げ直し |
| カメラ | 「いま」と「行きたい所」（俯瞰／サイコロの台／手番のコマ）を 6% ずつ近づける |

Cannon-es も Three.js と同じく `importmap` で CDN（cannon-es@0.20.0）から読み、`window.CANNON` に置く。Python からは `CANNON.Body.new(js(mass=1, shape=CANNON.Box.new(CANNON.Vec3.new(...))))`、毎コマ `phys.step(1/60, dt, 4)`。

## 検証

- `--check`：島とマス（山の位置・海の上・等間隔・分岐と合流）、手番の状態機械（振る → 3 回跳ぶ → カード → CPU が待って振る）、分かれ道（止まると選ぶ・ちょうどなら選ばない・性格ごとの確率 200 回）、出来事（＋／−／宝は 1 人だけ／休み／カード 9 種全部／ゴールは超えても止まる）、自動で 1 ゲーム 3 種（36〜40 手、同じ種は同じ結果）、板の大きさ、記録・音・状態行
- 端末：pty で 26 コマ/秒。スペースで振り、CPU が続く
- ブラウザ：Playwright（SwiftShader）で 23〜30 コマ/秒、エラー無し。指のはらいで 8 回投げ、分かれ道のボタン、37 手まで（CPU も物理のサイコロ）

## メモ

- 手番を進める `begin_turn()` を最初に書いたが条件が絡まり、`next_turn()`（次の人を探して休みを消費する）に書き直した
- 映り込み（`RoomEnvironment`）はそのままだと島の色が白く飛ぶ。`scene.environmentIntensity = 0.35`（g69 と同じ罠）
- サイコロの台を海に浮かべ、カメラを台に振る。投げた直後はサイコロが画面の上に飛び出すので、カメラは少し引いて高く
