# g25 チェスの CPU（先読み）

チェスの 4 段階目。ランダムに指していた CPU が、**先を読んで**指すようになりました。
駒の価値と位置で局面を採点し、相手も最善を指すとしてミニマックス（negamax）で読み、αβ 枝刈りで見なくていい枝を飛ばし、
持ち時間の中で深さを 1 ずつ増やします（反復深化）。指したあとに「何手読んで、何局面見て、どう評価したか」が出ます。

今回の主題は 3 つです。

- **ミニマックス（negamax）と αβ 枝刈り** — 「相手の最善の点に −1 を掛ける」で min と max を分けない。`math.inf` を初期値に
- **速くする** — 利きを「マスから逆引き」にして、葉では合法手を作らない。150 局面/秒 → 18,000 局面/秒
- **反復深化と時間制限** — `time.monotonic()` の締め切りを越えたら**例外で探索から抜ける**（`class TimeUp(Exception)`）

## 仕様

- **評価**: 駒の価値（P 100 / N 320 / B 330 / R 500 / Q 900）＋ 位置の点（駒ごとの 8×8 の表、黒は上下を裏返す）。手番側から見た点
- **探索**: negamax。メイトは `MATE − 手数` で「早いメイトほど高い」。50 手ルールと駒不足は 0 点
- **αβ**: 取る手（価値の高い駒から）と成る手を先に読む（`order_moves`）。3 手読みで 24,942 局面 → 3,229 局面（7.7 分の 1）
- **葉では合法手を作らない**: そのため 2 手メイト（3 プライ）は 4 手読みで見つかる。1 手メイトは 2 手読みで
- **反復深化**: 深さ 1, 2, 3… と読み直し、締め切りを越えたら最後に読み切った深さの手。メイトを見つけたら打ち切り
- **速さ**: この Mac で 11,000〜18,000 局面/秒。1 秒で 4 手読み（初期局面）

## メモ

### negamax — min と max を分けない

```python
def negamax(board, depth, alpha, beta, ply, deadline, stats):
    ...
    best = -math.inf
    for move in order_moves(board, moves):
        score = -negamax(make_move(board, move), depth - 1, -beta, -alpha, ply + 1, deadline, stats)
        best = max(best, score)
        alpha = max(alpha, score)
        if alpha >= beta:
            break
    return best
```

ミニマックスは「自分は最大を、相手は最小を選ぶ」。評価を**手番側から見た点**にしておくと、相手の番の最善は「相手から見た最大」で、
それに −1 を掛ければ自分から見た点になります。だから関数は 1 つ、`max` だけ。`evaluate` が手番で符号を反転しているのはそのためです。
`-math.inf` は「まだ何も見ていない」の初期値。`float("inf")` と同じですが名前で読めます。

### αβ 枝刈り — 「相手はこの枝を選ばない」

`alpha` は自分が既に確保した点、`beta` は相手が既に確保した点。ある手の点が `beta` 以上なら、相手はそもそもこの局面に来ない（もっと良い選択肢を持っている）ので、
残りの手を読む意味がない。**良い手を先に読むほど早く `beta` に届く**ので、取る手と成る手を前に出す `order_moves` がセットです。

### メイトの点は「早いほど高い」

`-MATE + ply`。3 プライ先でメイトされる局面は `-MATE + 3`、1 プライ先なら `-MATE + 1`（もっと悪い）。
これで CPU は「メイトできるならいちばん早い手順」を選び、「メイトされるならいちばん粘る手順」を選びます。

### 速くする — 測ってから直す

最初の版は 150 局面/秒で、1 秒で 2 手しか読めませんでした。遅い理由は 2 つ。

1. 合法手の判定で `attacked`（利きの集合）を**両方の色ぶん全部**作っていた。必要なのは「キングのマスに利きがあるか」だけ。
   `is_attacked(board, square, color)` は**マスから逆向きに**ナイト・キング・ポーン・飛び駒を探すので、駒を全部回さない
2. 葉（`depth == 0`）でも合法手を作っていた。葉はいちばん数が多いので、そこでは評価だけにした

この 2 つで 18,000 局面/秒、120 倍。代わりに葉のメイトは見えなくなるので、2 手メイトは 4 手読みが要ります（検証の表のとおり）。
`stats["nodes"]` を数えて `局面/秒` を出す習慣が、どこを直すべきかを教えてくれます。

### 反復深化 — 時間で止めるには「途中から抜ける」

```python
class TimeUp(Exception):
    """考える時間が切れた。探索の途中から一気に抜けるための例外。"""

    if deadline is not None and stats["nodes"] % 256 == 0 and time.monotonic() > deadline:
        raise TimeUp
```

深さ N の探索は再帰の奥深くにいるので、`return` で少しずつ戻るのは面倒。**例外なら 1 行で最上位まで抜けられます**。
`think` は深さ 1 から順に `search` を呼び、`TimeUp` を受けたら「最後に読み切った深さの手」を返す。
浅い深さの結果は無駄になりますが、深さが 1 増えると局面数は数倍になるので、浅いぶんの合計は深いぶんより小さい——だから反復深化は損をしません。
`time.monotonic()` は時計合わせの影響を受けない経過時間。256 局面に 1 回だけ見るのは、時計を読む回数を減らすため。

### 位置の点（Piece-Square Table）

ナイトは中央で +20、隅で −50。ポーンは進むほど高い。キングは序盤は隅で +20〜30。
表は白の向き（8 段目が先頭）で書き、黒は `7 - rank` を反転させて同じ表を使います。数値は古典的な「Simplified Evaluation Function」の値です。
