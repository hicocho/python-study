# g78 小惑星をよける（3D）

宇宙船の後ろから見た視点で、迫ってくる小惑星をよける。**3D はライブラリを使わず自分で書く。**

**ブラウザ版**: https://hicocho.github.io/python-study/g78/

```bash
python3 main.py            # 遊ぶ（スペースで始める。← → ↑ ↓ か w a s d。p で一時停止、q でやめる）
python3 main.py --check    # 決まりを確かめる
python3 main.py --shot     # 場面を PNG に書き出す
```

ベストは `records.json`（この階層。遊んだ結果なので git には入れない）に残る。ブラウザ版は localStorage。

## 3D の作り方（今回の主題）

```
   3D の点 (x, y, z)
     ↓ 回転 ―― x・y・z 軸まわりの 2D 回転を 3 回
     ↓ 透視投影 ―― 遠いものは小さく：x' = CX + FOCUS × x / z
     ↓ 128 × 80 のドット画面
```

3D を感じさせる 4 つの手がかりを全部入れた。

| 手がかり | どう作ったか |
|---|---|
| **遠近** | `project()`：z で割る。近づくほど大きく、真ん中から離れる |
| **視差** | 星は全部同じ速さで動くが、近い星ほど画面上で速く流れる（割り算の結果） |
| **隠面** | こちらを向いていない面は描かない（法線と視線の内積）。残った面は奥から順に塗る（画家のアルゴリズム） |
| **陰影** | 面の法線と光の向きの内積で明るさを決める |

```python

    def cross(self, other): ...    # 外積。2 本の辺に直角な向き＝面の向き（法線）
```

- 小惑星は**正二十面体の頂点をでこぼこにずらした**もの（12 頂点・20 面）。種で形が決まる
- 面の表裏は `outward()` で自動でそろえる（重心から見て外を向くように）。手で書くと裏返る
- 多角形の塗りは横 1 行ずつ、辺との交点の間を埋める（スキャンライン）

## 3D っぽさを足したもの（2 回目）

| 足したもの | 何が変わるか |
|---|---|
| **カメラが自機を追って傾く** | 曲がると画面全体が傾き、カメラが少し遅れて横についてくる。「自分がそこにいる」感 |
| **トンネルの輪** | 等間隔の輪が手前へ流れる。奥行きと速さが**測れる**ようになる（遠近法の線） |
| **霧** | 遠いものほど背景の色に溶ける（空気遠近法）。奥へ消えていく感じ |

```python
def view(p: V, cam: Camera = Camera()) -> V:
    """世界の点を「カメラから見た点」にする。カメラの位置を引いてから、傾きのぶん逆に回す。"""
    q = V(p.x - cam.x, p.y - EYE, p.z)
    return rotate(q, 0, 0, -cam.roll)
```

カメラを「世界の中の物」にしたのがポイント。すべての点を `view()` でカメラから見た座標に直してから
`project()` に渡す。カメラを動かしても投影の式は変わらない。

## 仕様

- 128 × 80 ドット、1 コマ 1/30 秒の固定刻み（g64 と同じ）。ブラウザは同じ式を 2 倍の板（256 × 160）で回す
- 小惑星は z = 48 で生まれ、速さ 10（よけるたび +0.35、上限 34）で迫る
- 自機は画面に収まる範囲（x ±3.2、y −0.8〜2.6）だけ動ける。小惑星もその範囲に出る
- ぶつかると ♥ −1 と 1 秒の点滅（無敵）。3 回で終わり
- **点**：通り過ぎた小惑星との近さで決まる。ぶつかる境目（縁 + 0.55）からの余りが
  0.5 以内なら「スレスレ +3」、1.2 以内なら「近い +2」、それより遠くは +1
- **コンボ**：スレスレ・近いが続くと ×2 ×3 …（上限 ×5）。遠くをよけるか、ぶつかると 0 に戻る
- **ゲートとステージ**：よけた数が 10 に達するたびに緑の輪（半径 2）が来る。ゲートが来る間は小惑星を出さない。
  中を通れば ♥ +1、速さ +1.5、ステージ +1。外しても罰は無い
- **小惑星の出方**：ステージ 1 は 1 個だけ。2 で左右 2 個、3 で横一列の帯（穴が 1 つ）、4 で大きいの（半径 2〜2.6）が加わる。
  同じコマに何個も通り過ぎたら（帯など）、いちばん近い 1 個で点を決め、「よけた」は 1
- **スタート前**は星と輪が流れているだけ（自機は動かせる）。スペース / p / Enter で始まり、同じキーで一時停止・再開
- **速さの実感**：速いほど焦点距離を縮めて広角に（62 → 43）。星は前のコマの位置から線を引く（流線）
- **危険色**：いまの位置のままだとぶつかる小惑星は赤みがかった色で描く
- **ベスト**：終わったとき、点・最高コンボ・よけた数の最大を残す。点を超えたら「ベスト更新！」と上がる 4 音
- **揺れ**：ぶつかると 0.45 秒、スレスレなら 0.12 秒カメラが揺れる。画面の縁も光る（スレスレは黄、ぶつかったら赤）
- 音：よけた（高く短く）・ぶつかった（低く長く）・おしまい。g73 と同じ作り方

## 板（`Screen`）の作り

画面は `list[bytearray]`——1 行が `RGB × 幅` のバイト列。面を塗るのは走査線ごとに
`row[left*3:(right+1)*3] = paint * (right - left + 1)` の**スライス代入 1 回**で済ませる。
ドットを 1 つずつ置くより速く、板を 2 倍（256 × 160、面積 4 倍）にしても描く時間は 1.0 ms → 1.1 ms。
`project(p, scale)` の `scale` は板の幅 ÷ 128 で、端末（1.0）とブラウザ（2.0）が同じ式を使う。

```python
def fill(self, points, color):        # 走査線で塗る
    for y in range(top, bottom + 1):
        ...  # 辺との交点 xs を集める
        self.rows[y][left * 3:(right + 1) * 3] = paint * (right - left + 1)
```

端末は 1 ドット = 1 文字幅（▀ で縦 2 ドット）なので 128 × 80 が上限。細かくしたいのはブラウザだけ。

## スレスレとコンボ（2 回目の直し）

「よけた数」だけだと、遠くをふらふら逃げるのが正解になって単調だった。近さで点を変える。

```python
def judge(self, rock: Rock) -> str:
    gap = math.dist((rock.pos.x, rock.pos.y), (self.ship.x, self.ship.y)) - rock.radius - HIT_GAP
    if gap < 0:          return "hit"
    if gap < GRAZE_GAP:  return "graze"
    if gap < NEAR_GAP:   return "near"
    return "pass"
```

`update()` が返す出来事は `EVENTS = ("pass", "near", "graze", "hit", "over")` の 5 つ。
同じコマに 2 つ起きたら、目立つ方（後ろ）を返す。

**揺れはカメラをずらす**。`Camera` に `jolt_x / jolt_y` を足し、`view()` で引く。画面をずらすのではなく
カメラ（世界の中の物）をずらすので、近い物ほど大きく揺れて見える。揺れの量は `sin(time × 71)` のように
時間から決める——乱数を使うと端末とブラウザで違う絵になる。

## ベスト記録（3 回目の直し）

`Best` は `dump()`（JSON の文字列）と `parse()`（壊れていても 0 から）を持つ小さなデータクラス。
置き場だけが端末（`records.json`）とブラウザ（`localStorage`）で違い、中身の形は同じ——g77 の `History` と同じ作り。
「終わった瞬間」は `update()` が `"over"` を返したときで、端末の `run()` もブラウザの `loop()` もそこで
`best.take(world)` → 保存 → 更新なら音を `"best"` に差し替える。

## ゲートとステージ（4 回目の直し）

小惑星の「出方」を関数にして表に入れた。ステージが進むと使える出方が増える。

```python
PATTERNS = {"one": spawn_one, "pair": spawn_pair, "band": spawn_band, "big": spawn_big}
STAGE_ORDER = ("one", "pair", "band", "big")

def stage_patterns(stage):            # ステージ 1 → ("one",)、3 → ("one", "pair", "band")
    return STAGE_ORDER[:max(1, min(stage, len(STAGE_ORDER)))]

pattern = self.luck.choice(stage_patterns(self.stage))
self.rocks.extend(PATTERNS[pattern](self))
```

出方を 1 つ足すのは、関数を 1 つ書いて表に 1 行足すだけ。`update()` は触らない。

帯のように**同じコマに何個も通り過ぎる**ときは、いちばん近い 1 個だけで判定する（`min(passing, key=self.gap)`）。
1 個ずつ判定すると、穴を抜けたのに遠い方の岩で「+1、コンボ途切れ」になってしまう。

## 速さを目で感じさせる（5 回目の直し・完成）

速さ 10 → 34 で数字は 3 倍になるが、見た目はほとんど変わらなかった。手がかりを 2 つ足した。

- **広角**：`project()` に `focus` を渡せるようにし、`World.focus` が速さから焦点距離を決める。
  焦点距離が短いほど同じ点が真ん中寄りに映り、手前のものが端へ流れる速さが上がる
- **流線**：星を「前のコマの位置 → 今の位置」の線で描く。`z + speed × STEP × STREAK` が前の位置。
  透視投影の割り算のおかげで、近い星ほど・速いほど勝手に長くなる（3 倍の速さで流線は 2.5 倍）

**危険色**は `World.dangerous(rock)`——「自機がいまの位置のままだと、この小惑星にぶつかるか」を
`gap() < 0` で判定して色を変えるだけ。判定の関数が 1 つあると、演出はそれを呼ぶだけで済む。

**スタート前と一時停止**は `World.started / paused`。`update()` はスタート前なら星と輪だけ動かして返り、
一時停止中は何もしない。時計（`time`）はスタートしてから進む——出す間隔が時間で決まるので、
待っている間に難しくなってはいけない。キーは 1 つ（`go`）で「始める → 止める → つづける」を回す。

## メモ

- **面の表裏は自動でそろえる。** 自機の面を手で書いたら裏返っていて、暗い塊に見えた。
  凸な立体なら「重心から見て外向き」で決められるので、`outward()` に任せる
- **視点を少し高くする**（`EYE`）と、自機が画面の下寄りに映って「後ろから見ている」感じになる
- **自機の動ける範囲は「画面に収まる幅」から逆算**した。z=4 で ±3.2。それより広いと画面の外へ出る
- `CX, CY = …` のタプル代入が切り出しに拾われなかった（4 回目）。1 行 1 つに
- **出来事を 1 つ足したら音の表も足す。** `near` を返すようにしたら `Speaker.say()` が `KeyError` で止まり、
  ブラウザは音もなく凍った（`--check` は通っていた）。`SOUNDS = EVENTS` にして、
  「返す出来事には全部音がある」を `--check` に入れた
