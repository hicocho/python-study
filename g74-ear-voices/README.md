# g74 耳コピ2（楽器を選ぶ）

[g73](../g73-ear-piano/) と同じ遊びで、**楽器を選べる**——ピアノ・エレクトーン・ギター・ベース・木琴。
お題も鍵盤も、選んだ楽器で鳴る。どれも Python で波から作った音で、音源ファイルは 1 つもない。

**ブラウザ版**: https://hicocho.github.io/python-study/g74/

```bash
python3 main.py            # 遊ぶ（Tab で楽器を切り替える）
python3 main.py --check    # 決まりを確かめる
python3 main.py --wav 0    # 1 曲目を楽器ぜんぶで wav に書き出す
```

## 今回の主題

**同じ高さの音でも、波の作り方で楽器が変わる。** どの楽器も「音の番号と長さを受けて標本の列を返す」
同じ形（`Voice`）なので、差し替えるだけで済む。

```python
Voice: TypeAlias = Callable[[int, float], array]    # 音の番号と長さを受けて、標本の列を返すもの
```

**1. ピアノ — 倍音を重ねて、打った瞬間から減衰させる**

```python
PIANO = ((1, 1.0), (2, 0.6), (3, 0.3), (4, 0.15), (5, 0.08))     # 倍音とその強さ

    def wave_at(i: int) -> float:
        t = i / RATE
        value = sum(s * math.sin(math.tau * hz * k * t) * math.exp(-k * t) for k, s in PIANO)
        return shape(i, count, attack=RATE / 200) * math.exp(-3.5 * t) * value
```

高い倍音ほど早く消える（`exp(-k t)`）。これが「打った直後は明るく、すぐ丸くなる」ピアノらしさ。

**2. エレクトーン — 倍音を足し合わせて持続させる（`functools.reduce`）**

```python
DRAWBARS = ((0.5, 0.8), (1, 1.0), (2, 0.7), (3, 0.4), (4, 0.3), (6, 0.15), (8, 0.1))

        value = reduce(lambda total, bar: total + bar[1] * math.sin(math.tau * bar[0] * phase),
                       DRAWBARS, 0.0) / LOUD_ORGAN
```

本物のオルガンは「ドローバー」を引いて倍音の量を決める。それを表にしたのが `DRAWBARS`。
`reduce` で表を 1 つの波に畳む。減衰しないかわりに、ゆれ（トレモロ）を少し乗せる。

**3. ギター・ベース — 弦をはじく（Karplus-Strong、`collections.deque(maxlen=)`）**

```python
    length = max(2, int(RATE / pitch_hz(note)))     # 一周が音の高さになる
    luck = random.Random(1)                         # 種を固定。端末とブラウザで同じ雑音にする
    string = deque((luck.uniform(-1, 1) for _ in range(length)), maxlen=length)

    def wave_at(i: int) -> float:
        first = string[0]
        value = damp * (blend * first + (1 - blend) * last)
        string.append(value)
        ...
```

弦の長さぶんの**雑音**を用意し、先頭を取り出しては「となりと平均して」末尾に戻す。
それだけで、雑音が一周ごとに丸くなって弦の音になる。`deque(maxlen=)` が弦そのもの。
平均するたびに高い成分から消えるので、はじいた直後は明るく、あとは太く残る。
ベースは同じ仕組みを 1 オクターブ下で、平均を強めに。

**4. 木琴 — 少ない倍音を短く**

基音と、4 倍近く（3.98 倍）の高い倍音を 1 つだけ。どちらも速く減衰させる。
整数倍からわざと外すと、金属っぽい響きになる。

## 遊び方

g73 と同じ。足したのは楽器の切り替えだけ。

```
 Tab      楽器を順に切り替える（ブラウザは楽器のボタンで直接）
```

楽器を変えると、いまの音を 1 つ鳴らして聞かせる。曲や打ち込みには触らない。

## 仕様

- 楽器 5 種。`VOICES` の表に (名前, 関数) で並べてある。足すなら表に 1 行
- 音の大きさは 5 種ともそろえた（いちばん大きい標本 9,000〜11,300、頭打ちなし）
- 弦の雑音は `random.Random(1)` で種を固定——**同じ呼び方なら毎回同じ bytes**。
  端末とブラウザで wav が 1 バイトも違わないのは、これがあるから
- `--check` が見るもの: 5 種とも別の音か／頭打ちしていないか／毎回同じか／
  エレクトーンは持続しピアノは減衰するか／g73 の検査ぜんぶ

## メモ

- **楽器の違いは「倍音」と「減衰」の 2 つでほぼ決まる。** 5 種を作ってみて、
  倍音が多いほど明るく、減衰が速いほど打楽器っぽくなる。木琴は倍音を 1 つ、整数倍から外すだけで金属になった
- **Karplus-Strong は「雑音を遅らせて平均する」だけ。** 波の式を 1 つも書いていないのに弦の音になる。
  `deque(maxlen=)` にすると `append` で古いものが押し出されるので、弦の一周がそのまま書ける
- **雑音の種を固定しないと、端末とブラウザで違う wav になる。** 「同じ bytes」を守るために `Random(1)`
- **「持続しているか」を測る場所を間違えた。** 音の末尾で測ったら、消え方（フェード）の中で測っていて
  エレクトーンまで「減衰」になった。消え始める前（6〜8 割の位置）で測る
- 音の生成はブラウザで 7 音 0.6〜1.0 秒。作った音は取っておくので、同じ音は待たない
