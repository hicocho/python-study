# g79 3D レース

曲がって上下する周回コースを、CPU カー 3 台と 3 周で競う。**3D は g78 と同じく自分で書く。**
g78 で避けて通った 2 つ——**カメラを回す**と**ニアクリッピング**——が今回の主題。

**ブラウザ版**: https://hicocho.github.io/python-study/g79/

```bash
python3 main.py            # 遊ぶ（スペースで始める。← → で曲がる、↑ アクセル、↓ ブレーキ。q でやめる）
python3 main.py --check    # 決まりを確かめる
python3 main.py --shot     # 場面を PNG に書き出す
python3 main.py --map      # コースを真上から PNG に
```

## 3D で新しく覚えるところ

```
   世界の点 (x, y, z)
     ↓ view()   カメラの位置を引き、車の向き（yaw）のぶん逆に回し、少し見下ろす   ← 新
     ↓ clip_near()  z = NEAR の面で多角形を切る                                    ← 新
     ↓ project() 透視投影 x' = CX + FOCUS × x / z（g78 と同じ）
     ↓ 128 × 80 のドット板（ブラウザは 256 × 160）
```

### カメラを回す

```python
def view(p: V, cam: Camera) -> V:
    q = p - cam.pos
    q = rotate(q, 0.0, -cam.yaw, 0.0)     # 車が右を向けば、世界は左へ回る
    return rotate(q, -TILT, 0.0, 0.0)     # 少し見下ろす → 地平線が真ん中より上に
```

g78 のカメラは横にずれて傾くだけで、向きは常に +z だった。レースでは車がどの向きにも進むので、
**カメラの向きのぶん世界を逆に回してから**投影する。式は `rotate()` を 1 回呼ぶだけ。

### ニアクリッピング

```python
def clip_near(points: list[V]) -> list[V]:
    kept = []
    for i in range(len(points)):
        a, b = points[i], points[(i + 1) % len(points)]
        a_in, b_in = a.z >= NEAR, b.z >= NEAR
        if a_in:
            kept.append(a)
        if a_in != b_in:                          # またぐ辺 → 交点を足す
            t = (NEAR - a.z) / (b.z - a.z)
            kept.append(a + (b - a).scale(t))
    return kept
```

道は視点の足元を通る。断面の 1 つが視点の後ろ（z < NEAR）に来ると、そのまま `x / z` で割った値が
飛んで絵が破綻する（g78 は「手前は描かない」で逃げていた）。面をまたぐ辺を交点で切って手前側だけ残す
（Sutherland–Hodgman の 1 面ぶん）。凸多角形は切っても凸のままなので、`Screen.fill` がそのまま使える。

### 曲線からメッシュ

制御点 11 個を **Catmull-Rom** でつなぎ（制御点を必ず通る曲線）、1 区間を 20 分割して断面 220 個にする。
断面ごとに「進む向き」と「右手」を持ち、`edge(i, offset)` で中心から右へ offset の点が取れる。
道は隣り合う断面の左端・右端を結んだ四角の帯。路肩・草も同じ帯を横にずらしただけ。

### 坂

`Track.locate(pos, hint)` が一番近い断面を（前回の断面の近くから）探し、道のり・横ずれ・**道の高さ**を返す。
車の y はこの高さ。断面の間は直線で補う。

## 見た目（2 回目の直し：ポリゴンが大きすぎる → 車らしく、風景らしく）

- **車**：横顔（`PROFILE`、8 点）を左右に押し出した車体。面ごとに材質を持ち（`car_body()` が返す `kinds`）、
  フロントガラス・リアウィンドウはガラス色、下回りは暗い色。タイヤは 8 角柱 × 4（`wheel()`）、横の窓は車体の
  面のすぐ外側に貼る四角、ヘッドライトとテールランプは小さな四角。足元に影（平たい 8 角形）。
  `draw_solid()` に `colors`（面ごとの色）を足した
- **道**：縁石（赤白 0.55 m）・土（1 m）・白線（端 2 本と真ん中の破線）。遠くは白線と土を省く（1 ドットにもならない）
- **風景**：空のグラデーション、雲、遠い山と近い山（`ridge()`：sin を足した決まった形。**向きだけで決まる**ので
  曲がると横に流れる）、針葉樹（3 段の三角）・広葉樹（丸を 2 つ重ねる）・茂み
- **板**：ブラウザは 3 倍（384 × 240）。19〜20 コマ/秒（2 倍なら 23）
- 速さ：`view()` は「回して足す」だけなので、断面ごとに中心と右手を 1 回ずつ変換して `center + right × offset` で
  12 点を作る（1 コマ 1200 回の回転が 110 回に）。1 コマ 4.5 ms（128×80）〜7 ms（384×240）

## 車の動き

- アクセル +16 m/s²、ブレーキ −26、空気抵抗 0.36 × 速さ → 最高速 ≈ 44 m/s（160 km/h）
- 曲がる速さ = `TURN × (速さ / (速さ + GRIP)) × (1 − 速さ / 88)`。止まっていては曲がれず、**速いほど曲がりにくい**
- 草の上は抵抗 +1.4 × 速さ（1 秒で 30 → 5 m/s）。壁は無い
- CPU カーはコースの道のり `s` で進む。直線の速さ `pace` × カーブでの減速 `max(0.65, 1 − bend)`。
  自動操縦（1 周 19 秒）と競る速さになるよう**測って決めた**（CPU の 1 周 ≈ 23 / 21 / 19 秒）
- 接触（2.6 m 以内）：自分の速さ 55%、横へ 1.2 m 押し出し。CPU は 0.8 秒だけ半分の速さ

## 検証

- `--check`：コースの断面と道のり、ニアクリッピング（切り口が NEAR の面の上・全部後ろなら空）、
  カメラ（右を向けば +x が正面）、加速・旋回・制動、速いほど曲がりにくい、草の減速、
  自動操縦で 3 周（出来事の数、順位）、順位、接触、板の大きさ、記録、音
- 端末：pty で 30 コマ/秒、↑ を押し続けて 110 km/h
- ブラウザ：Playwright で 19〜20 コマ/秒（3 倍の板）、3・2・1・GO → ↑ で 104 km/h、エラーなし

## メモ

- **スタートは最後尾から。** CPU を後ろに並べたら、加速の遅い自分に後ろから追突して開始直後に減速した
- 制御点の並びで「まっすぐ」にならない。スタート直線は前後の制御点を同じ x に置く（Catmull-Rom の接線は前後の点の差）
- `locate()` は前回の断面の近く（−6〜+14）だけ探す。1 コマで進むのは 1〜2 断面なので足りる
- 曲がる速さの式を `(1 − 速さ/100)` にしたら 10 m/s と 40 m/s で同じになってしまった。検査で気づいた
