# g13 迷路レース

深さ優先で「実際に歩く」探索ロボットと、同じ迷路で競走する CLI ゲームです。
`--show DFS` で探索が 1 歩ずつ進むアニメを、`--compare` で DFS・BFS・A* の比較表を出せます。

g12 との 2 段階の連作で、g12 が「作る・歩く・最短路」、この g13 が「探索を見る・ロボットと競走」です。

今回の主題は 3 つです。

- **再帰 → 明示的なスタック** — g12 の穴掘り法を `while stack` で書き直し、`sys.setrecursionlimit` を不要にする
- **探索をジェネレータにする** — DFS・BFS・A* が「見たマス」を 1 つずつ `yield` し、同じ関数でアニメも計測もレースもできる
- **`heapq` の優先度付きキュー** — A* は「ここまでの歩数 + ゴールまでの見込み」が小さいマスから見る

`distance()` / `astar_steps()` / `robot_walk()` / `trace()`）、そして `class Game` を **1 文字も変えずに**持ってきています
（`ast` で切り出して文字列比較で確認済み）。

持ってこなかったのは `maze_text()` / `show_search()` / `measure()` と `raw_mode()` / `read_key()` / `race()` /
`parse_args()` / `main()`、それに `Game.render()` だけ。違うのは**入口と出口**で、

- 入口：`select` で待つ生キー入力 → `asyncio` の時計とキーイベント

## 仕様

- 迷路は g12 と同じ穴掘り法（再帰なし）。同じ左上から出て、右下のゴールに先に着いたほうの勝ち
- **ロボット**は深さ優先で「実際に歩く」。まだ行っていない隣を 1 つ選んで進み、行き止まりなら来た道を 1 マス戻る。
  21×21 で平均 160 歩（最短の 1.8 倍）
- **DFS / BFS / A\*** は「見たマス」を 1 つずつ返すジェネレータ。迷路は木なので、3 つとも見つける経路は最短
- A\* の見込みはマンハッタン距離。迷路では壁を無視した見込みなので、BFS よりは減るが DFS に負けることも多い
- `--compare` は同じ迷路で 3 つを回し、見たマス数・経路の歩数・時間（`perf_counter`）を表にする

## メモ

### 再帰をスタックに書き換える

g12 の `carve` は再帰でした。同じ動きを、**来た道をリストに積む**ことで再帰なしにできます。

```python
    stack = [(row, col)]
    while stack:
        r, c = stack[-1]                                    # 取り出さずに、いちばん上を見る
        options = open_directions(grid, r, c)
        if not options:
            stack.pop()                                     # 行き止まり。来た道を 1 つ戻る
            continue
        dr, dc = random.choice(options)
        ...
        stack.append((r + dr, c + dc))                      # 掘った先へ進む
```

再帰版で「関数を呼ぶ」だったところが `append`、「関数から戻る」だったところが `pop`。
Python が裏で持っていた呼び出しの積み重ねを、自分のリストで持つだけです。
これで 201×201（部屋 10000）も `setrecursionlimit` なしで通ります。

`stack[-1]` で**取り出さずに見る**のがポイント。掘れる方向が残っているあいだは同じ場所に居続けるので、
取り出してしまうと戻れなくなります。

### 探索をジェネレータにすると、1 つの関数が 3 役になる

```python
def bfs_steps(grid, start, goal, came_from):
    queue = deque([start])
    came_from[start] = None
    while queue:
        pos = queue.popleft()
        yield pos
        if pos == goal:
            return
        ...
```

g12 の `shortest_path` は「経路を返す」関数でした。今回は**見たマスを 1 つずつ `yield` する**形にしています。
すると同じ関数が、

- `for pos in bfs_steps(...)` で 1 歩ずつ描けば**アニメ**
- `sum(1 for _ in bfs_steps(...))` で使い切れば**見たマス数**（`measure`）
- ブラウザ版では `await asyncio.sleep` を挟んで**同じジェネレータ**を回す

g10 の `yield` は「必要な分だけ作る」ためでしたが、ここでは**途中経過を外に見せる**ために使っています。
経路は `came_from` に書き込んでおき、終わってから `trace()` でたどります。

### DFS と BFS の違いは、入れ物の端だけ

`dfs_steps` と `bfs_steps` は 1 行しか違いません。`stack.pop()`（最後に入れたものから）か、
`queue.popleft()`（最初に入れたものから）か。**同じコードで、取り出す端を変えるだけで探索の形が変わる**——
g12 で「どちらの端から取るかで探索の形が変わる」と書いたことの実物です。

### `heapq` — いちばん小さいものが先に出てくる

```python
    heap = [(distance(start, goal), next(order), start)]
    ...
        _, _, pos = heappop(heap)
        ...
            heappush(heap, (new_cost + distance(nxt, goal), next(order), nxt))
```

A* は「ここまでの歩数 + ゴールまでの見込み」が**小さい順**に見たい。並べ替えを毎回やると遅いので、
`heapq` に「入れると勝手に小さいものが先頭に来る」リストを任せます。タプルは先頭から比べられるので、
`(点数, 順番, マス)` の形にしておけば点数で並びます。

真ん中の `next(order)` は `itertools.count()` から取る通し番号で、**点数が同じときに先に入れたほうを先に**出すため。
これが無いと同点のとき 3 つ目のタプル（座標）で比べられ、意図しない順になります。

### 迷路では A* が思ったほど効かない

```
31×31 の迷路で 3 つを比べる

探索  見たマス    経路      時間
DFS        241     228   0.10 ms
BFS        347     228   0.14 ms
A*         321     228   0.21 ms
```

A* はマンハッタン距離を見込みにしますが、迷路の壁を無視した見込みなので、
「ゴールに近いのに壁で回り込む」場所でだまされます。木の迷路では DFS が意外と少ない歩数で着くことも多い。
**アルゴリズムの優劣は問題の形で決まる**——それを自分の目で見るための `--compare` です。

### ロボットは `dfs_steps` ではなく `robot_walk`

`dfs_steps` はスタックから取り出したマスを `yield` するので、行き止まりの次は**離れた場所へ飛びます**。
ロボットが物理的に歩くには、戻る道も 1 マスずつ通らないといけない。

```python
        if options:
            ...
            yield nxt                                       # 前へ 1 歩
        else:
            stack.pop()
            if stack:
                yield stack[-1]                             # 戻る 1 歩
```

`robot_walk` は「進む 1 歩」も「戻る 1 歩」も `yield` します。これは穴掘り法のスタックとまったく同じ形で、
掘るか歩くかが違うだけ。**ステップ 1 で書いたコードが、ステップ 5 のロボットになります。**

### ジェネレータを「持っておく」

```python
        self.walker = robot_walk(self.maze, self.start, self.goal)
        next(self.walker)
    ...
    def tick(self):
        ...
        self.robot = next(self.walker)
```

`Game` はロボットの歩みを**全部計算してリストに持つのではなく**、ジェネレータをそのまま持ちます。
`tick()` のたびに `next()` で 1 歩もらう。ロボットが「どこまで来たか」はジェネレータの中に残っているので、
`Game` 側にスタックも訪問済みも要りません。

### 時計はキーを待つ時間

```python
            key = read_key(TICK_SECONDS)
            ...
            game.tick()
```

g07〜g09 と同じ形で、`select` が 0.05 秒待つあいだにキーが来なければ `None`。
その 0.05 秒がそのままゲームの時計になり、`tick()` を 3 回に 1 回ロボットが動きます。
ブラウザ版はこの待ち時間を `await asyncio.sleep(TICK_SECONDS)` に置き換えるだけです。

### 勝てるようにできている

ロボットは平均で最短の 1.8 倍歩きます。0.15 秒に 1 歩なので 21×21 で 24 秒ほど。
人が最短路を 1 秒に 4 歩で歩けば 22 秒。**最短路を迷わず歩けばだいたい勝てて、迷うと負ける**あたりに合わせました
（100 レースを「1 ティックに 25〜50% の確率で最短路を 1 歩」の人で回すと 86 勝 14 敗）。
