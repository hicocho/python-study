# g81 エア・スラローム（3D フライト）

（もとの名前は「軽飛行機で輪をくぐる」。2026-09-17 に改名）

峡谷を低空で縫い、130 m おきの輪を順にくぐってタイムを競う。コース 3 つ（峡谷・海岸・高原）＋種から作るランダム。狭い峡谷・三連橋・S 字・トンネル・滝の上昇。外の視点で自機が見える。
**3D は g78〜g80 と同じく自分で書く。** g79（yaw）・g80（yaw + pitch）に続いて、今回で**3 軸の回転**がそろう。

最初の版は「山の上に輪 12 個・コックピット視点・外したら戻る」だったが、**「全然おもしろくない」**（やることが少ない・速さが無い・視点が狭い）
と言われて作り替えた。輪は 300〜550 m おきで次の出来事まで 5〜8 秒なにも起きず、地面が遠くて速さを感じなかった。

**ブラウザ版**: https://hicocho.github.io/python-study/g81/

```bash
python3 main.py            # 遊ぶ（スペースで始める。← → ロール、↑ ↓ 機首、w / s スロットル。q でやめる）
python3 main.py --check    # 決まりを確かめる
python3 main.py --shot     # 場面を PNG に書き出す
python3 main.py --map      # 地形と輪を真上から PNG に
```

ベスト（12 個くぐったタイム）は `records.json`（この階層。git には入れない）に残る。ブラウザ版は localStorage。

## 遊び方

- 3・2・1・GO で出発。**← → で翼を傾けると曲がる**（離すと水平に戻る）、**↑ ↓ で機首**（離すと水平へ）、スロットル 3 段階（55 / 80 / 110 m/s）。上昇で減速、降下で加速
- **橙の輪**が次。菱形の印が輪の場所、画面の外なら縁の矢印。輪の面をまたいだとき中心から 16 m 以内なら「くぐった」、外したら **+3 秒で次へ**（戻らない）。連続でくぐると連続数
- 谷の壁や地面にぶつかると法線の向きに跳ね返って減速（画面の縁が赤く）。岩柱は輪と輪の間、赤い橋は 5 つに 1 つの輪の上（輪はその下）
- タイム＝走行＋罰。40 個くぐったタイムがベスト

## 手ごたえ（2 回目の直し）

- **岩柱と橋に当たり判定**。前は見た目だけですり抜けた。岩柱は箱（9 × 9 m）、橋は梁（厚さ 4 m）と両端の柱。当たると壁と同じく跳ね返る
- **くぐるとブースト**：1 秒 +25 m/s。連続なら +0.3 秒ずつ（2.5 秒まで）。ぶつかると切れる。速度計が橙になる
- **低空ボーナス**：高度 8 m 未満を 1 秒続けるごとに −0.5 秒。高度計が黄色になる

## コースの山場（3 回目の直し）

道のりで 8 つの区間に分け（`SECTIONS` の表）、区間ごとに谷の幅・輪の並び・障害物を変える：

| 区間 | 何が違うか |
|---|---|
| 狭い峡谷 | 谷底の幅が半分（45 m）。細い岩柱が真ん中寄りに。輪は低く真ん中 |
| 三連橋 | 輪ごとに橋。3 本続けて橋の下をくぐる |
| S 字 | 制御点で急な S 字。輪が左右 ±22 m に大きく振れる |
| トンネル | 山を掘らずに残し、半径 28 m の筒で貫く。中は暗く（`DIM`）、天井に灯り。筒の壁で跳ね返る。手前 300 m の輪は筒の高さへ導く |
| 滝の上昇 | 谷底が 900 m で 180 m 上る。まわりの山も一緒に上げる（谷底だけ上げると空中の台地になった）。壁に滝 2 本 |

- `floor_width(k)`・`floor_at(k)`・`climb_lift(k)` が区間から決まり、`carve()` はそれを読むだけ
- トンネルの中は `tunnel_axis()` が筒の軸を返し、`collide()` は地面でなく筒の壁を「地面」として扱う
- 描く順：地形 → 木・輪・障害物・**筒の区切り**（奥から）→ 自機。筒は少し奥扱いにして、同じ場所の輪より先に描く

## 操縦（4 回目の直し）

- ← → を押している間は、傾きとは別に少しヨー。**カメラが曲がる先を見る**（6 回目でどちらも作り替え）

## コース 3 つ＋ランダム（5 回目の直し：「同じ地形を繰り返している？」）

地図は 1 枚で周回も繰り返しも無いが、毎回同じだった。コースを `COURSES` の表にして、名前を渡すと地図を作り直す（`load_course(name, seed)`）。

| コース | 制御点 | 区間 | 谷底 | 丘 |
|---|---|---|---|---|
| 峡谷 | 大きな S 字 | 谷→狭い峡谷→三連橋→S 字→谷→トンネル→谷→滝の上昇 | 40 m | 180 m |
| 海岸 | 海沿いをくねる | 橋が多い、狭い峡谷で締める | 12 m（川と水面が近い） | 120 m（低い） |
| 高原 | 高い山の間 | 狭い峡谷とトンネル 2 本、最後に上昇 | 150 m | 270 m（雪） |
| ランダム | 種から作る | 4 種を混ぜて並べ、2 回に 1 回は上昇で終わる | 20〜120 m | 150〜260 m |

- `random_course(seed)`：制御点は 340〜500 m の歩幅で向きを少しずつ変えながら 12 歩。地図の外や前の点に近いときは候補を何度か作って一番離れたものを採る
- 丘の模様も種でずらす（`hills()` の位相に種を足す）。ベストは**コースごと**（`Best.totals`）。ランダムは種が違っても 1 つ
- 端末：`--course 海岸`、`--seed 42`、始める前に `c` で切り替え。ブラウザ：ボタン（地図の作り直しに 0.6 秒）
- **ブラウザ版で地図が空だった。** 最初の読み込み `load_course("峡谷")` を「文」で書いたら切り出しに入らなかった（切り出すのは代入・関数・クラス）。
  `LOADED = load_course("峡谷")` と代入の形にして解決

## 操縦の手ごたえ（6 回目の直し：「操縦が難しいのはなぜ？」）

測ってみると、難しさの正体は 4 つだった：
1. **傾けてから曲がる 2 段階**——押して 0.3 秒遅れて曲がり始め、離しても 0.5〜1 秒曲がり続ける（行き過ぎ）
2. 機首 1.2 rad/s は 80 m/s で **1 秒に 27 m 上下**。輪の半径 16 m には敏感すぎる
3. カメラの先読み（0.9）で、傾けると**輪が画面の中で動く**
4. 最初から 80 m/s、輪は 1.6 秒おき

直し：
- **曲がりを押した量に直結**：`turning` が `roll_in` に 0.15 秒で追いつき、その量で曲がる（押して 0.2 秒で 8°、離すと行き過ぎ 8° で止まる）。
  翼の傾きは `turning` に合わせて見せるだけ。「傾きで曲がる」物理はやめた（アーケード寄りに徹する）
- 機首 1.2 → 0.7 rad/s。**高さの磁石**：次の輪の 120 m 手前から、高さの差を 1 秒に 80% 縮める（左右は触らない）
- 自機から真下へ落ちる線と影で、地面までの高さが見える
- カメラの先読み 0.9 → 0.3

## 音と演出（7 回目の直し）

- **エンジン音**（ブラウザだけ。g79 と同じ 0.5 秒の輪）：スロットルで段が変わり、速さで少し上がり、ブースト中はさらに高く。トンネルの中は反響で大きく
- くぐった音は**風切り**（雑音の山）に上がる 3 音を重ねる
- くぐった輪が**光の粒**になって散る、ブースト中は縁がうっすら橙、川の上を低く飛ぶと**水しぶき**

## 天気（8 回目の直し）

g80 の天気の表をそのまま持ってきた（`WEATHERS`：空の 2 色、霧の溶ける先と距離、明るさ、太陽、雨・雪の粒、地面を白くするか）。

## スマホの傾きで操縦（9 回目。ブラウザだけ）

`deviceorientation` の gamma（左右の傾き）を `roll_in`、beta（前後）を `pitch_in` に入れる。**連続値**なので、キーより細かく曲がれる
（`turning` は `roll_in` に追いつく作りなので、そのまま効く）。25° で押し切り、前後は持った角度 40° を基準に ±20°。
iPhone は「傾きで操縦」ボタンの処理の中で `DeviceOrientationEvent.requestPermission()` を呼ぶ必要がある（時計からは呼べない。音と同じ）。
サイトに使い方と注意（許可のダイアログ、回転ロック）を書いた。検証は Playwright で `deviceorientation` イベントを人工的に送って、方位と高度が変わること。

## 3D で新しく覚えるところ

### 3 軸の回転——向きを 3 本のベクトルで持つ

```python
def spin(v: V, axis: V, angle: float) -> V:
    """v を axis（単位ベクトル）のまわりに angle だけ回す（ロドリゲスの回転公式）。"""
    c, s = math.cos(angle), math.sin(angle)
    return v.scale(c) + axis.cross(v).scale(s) + axis.scale(axis.dot(v) * (1 - c))


class Frame(NamedTuple):
    forward: V; up: V; right: V                   # 互いに直角の単位ベクトル

    def roll(self, angle):   return Frame(self.forward, spin(self.up, self.forward, -angle), spin(self.right, self.forward, -angle))
    def pitch(self, angle):  return Frame(spin(self.forward, self.right, -angle), spin(self.up, self.right, -angle), self.right)
    def yaw(self, angle):    return Frame(spin(self.forward, self.up, angle), self.up, spin(self.right, self.up, angle))
```

g78 の `rotate()` は x・y・z 軸まわりだけ。飛行機は「機体の軸」まわりに回るので、**どの向きの軸でも回せる式**（ロドリゲス）が要る。
向きを角度 3 つでなく**前・上・右の 3 本**で持てば、ロールは前を固定して上と右を回すだけ。混ぜても順番の悩みが無い。
毎コマ少しずつ回すと直角と長さがずれるので `tidy()` で直す（前を正規化 → 右から前の成分を引く → 上 = 前 × 右）。

### 基底で見るカメラ

```python
def view(p: V, cam: Camera) -> V:
    q = p - cam.pos
    return V(q.dot(cam.frame.right), q.dot(cam.frame.up), q.dot(cam.frame.forward))
```

g79・g80 は角度で世界を逆に回した。向きを 3 本で持てば、**「その軸にどれだけ沿っているか」＝内積**がそのままカメラ座標。式は 3 行。

### ハイトマップと峡谷

丘 `hills(x, z)`（sin の重ね合わせ）を 64 × 64 マス（40 m）の表にしてから、**道すじに沿って峡谷を掘る**（`carve()`）：
道すじ（Catmull-Rom → 5 m おきの点）に近いマスほど低く、谷底（幅 90 m）は平ら、そこから 110 m かけて丘の高さへ戻る（smoothstep）。
谷底の高さは道すじに沿ってゆっくり上下する。`ground_at()` は 4 隅から双一次補間、`ground_normal()` は近くの高さの差から法線。
描くときは自機の近く 6 マスは 1 マスずつ、12 マスまでは 2 × 2、26 マスまでは 4 × 4 をまとめて。奥から順に塗る。

### 傾く地平線と追いかけるカメラ

地平線は「水平で無限に遠い向き」を 2 つ投影した**直線**。傾けば傾く。空はその線より上の半平面を大きな多角形で塗る。
どちら側が空かは、カメラの「上」を画面に投影して決める（画面の上は y の負——ここで 1 回間違えた）。
カメラは自機の後ろ 22 m・上 7 m を位置だけなめらかに追い、向きは自機を見る（`look` を前にして、上は世界の上を自機の傾きの 1/4 だけ回した向き）。
自機は部品（胴・主翼・尾翼・垂直尾翼・機首）を「前・上・右」の 3 本で組み立てて置く。プロペラは回る 3 枚。地面に影。

### 輪をくぐる判定

```python
now = self.side(ring)                          # 輪の面のどちら側か（符号つき距離）
if self.side_before < 0 <= now:                # 面をまたいだ
    t = self.side_before / (self.side_before - now)
    at = self.pos_before + (self.pos - self.pos_before).scale(t)   # またいだ瞬間の位置
    if (at - ring.pos).length() <= RING_R:
        ring.done = True
```

1 コマで 2〜3 m 進むので、「今の位置」でなく**またいだ瞬間の位置**（前と今の間を補間）で比べる。
面をまたがずに横や上を回って通り過ぎたとき（道のりが輪の 60 m 先）も「外した」。道のりは g79 の `locate()` と同じく前回の近くだけ探す。

## メモ

- **回転の符号は必ず具体的な点で確かめる。** ロールもピッチも最初は逆だった（`spin` の右ねじの向き）。「30° 傾けたら bank() が 30°」の検査で発覚
- 「上 = 右 × 前」と書いて上下が逆になった。**上 = 前 × 右**
- 輪の向きは「前の輪から来て次の輪へ行く向きの平均」。「次の輪へ行く向き」だけだと、最初の輪を横から通ることになった
- 自動操縦は機体座標の上下でなく**世界の上げ角**で機首を決める。傾いた機体の「上」は横を向いている
- **「↑ を押したあと上昇し続ける」**（Hicoさんの報告）。機首の限界（±50°）の判定が「限界を超えるなら動かさない」だったので、
  ぶつかって 50° より上を向いた瞬間から、水平へ戻る動きまで止めていた。限界の中では限界で止め、外にいるときは戻る向きだけ許す
- **「衝突後の上昇が戻らない」**（2 回目の報告）。跳ね返りの向きが「反射 + 法線」だったので、壁に正面からぶつかると
  ほぼ真上を向き（60°）、水平に戻るまでの 2 秒で 100 m 上がって谷から飛び出していた。跳ね返りの機首は 17° まで、
  水平に戻る速さも 0.8 → 1.4 rad/s に。ぶつかっても谷の中に留まる
- 作り替えで効いたのは「**次の出来事までの間を短く**」（輪 130 m おき＝1.5 秒に 1 回）と「**近くを物が通り過ぎる**」（谷の壁・木・岩柱）。
  速さの数字は同じでも、体感がまるで違う
