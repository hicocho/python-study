# g06 マインスイーパ

9×9 の盤に隠れた 10 個の地雷を避けて、それ以外のマスを全部開ける CLI ゲームです。
開いたマスには「周り 8 マスにある地雷の数」が出ます。0 なら周りも芋づる式に開きます。

## ブラウザ版

インストールせずに遊べます → **https://hicocho.github.io/python-study/g06/**

ソースは [`docs/g06/game.py`](../docs/g06/game.py)。CLI 版にある 9 個の関数のうち、
7 個を 1 文字も変えずに持ってきています。持ってこなかったのは `board_text()` と
`parse_move()`、それに `main()` だけ。つまり違うのは**入口と出口**で、`d3` という文字入力が
マスのクリックに、文字の盤面が 81 個の `<div>` に入れ替わっています。
ルールを決めている部分（数え上げ・連鎖・クリア判定）は 1 つも書き直していません。

## 遊び方（ターミナル）

```bash
python3 main.py
```

`d3` のように「列＋行」で入力すると、そのマスを開きます。
先頭に `f` を付けて `fd3` と入れると旗が立ち、もう一度入れると外れます。`q` でやめます。

```
   a b c d e f g h i
1  ■ ■ １ ・ ・ １ ■ ■ ■
2  ■ ■ １ ・ ・ １ ■ ■ ■
3  ■ ■ １ ・ ・ ２ ■ ■ ■
4  ■ ■ ２ ・ ・ １ ■ ■ ■
5  ■ ■ ２ ・ ・ １ ２ ■ ■
6  ■ Ｆ １ ・ ・ ・ １ １ ■
7  ■ １ ・ ・ ・ ・ ・ １ ■
8  ■ １ ・ ・ ・ ・ ・ ２ ■
9  ■ １ ・ ・ ・ ・ ・ ２ ■

開いたマス 49 / 残り地雷 9
どこを開く？（例 d3 / 旗は fd3 / q でやめる）> b6
```

- `■` まだ開けていないマス
- `・` 周りに地雷が無いマス（0）
- `１`〜`８` 周り 8 マスにある地雷の数
- `Ｆ` 自分で立てた旗
- `＊` 地雷（終わったときだけ見えます）

## 仕様

- 盤面は 9×9 の 81 マス。地雷は 10 個
- 地雷を置くのは**最初の一手のあと**。そのマスと周り 8 マスを避けて配置するので、初手で負けることはない
- 周りに地雷が 0 個のマスを開くと、その周り 8 マスも続けて開く（数字のマスにぶつかると止まる）
- 旗を立てたマスは開けない。旗は何個でも立てられる（当たっているかは判定しない）
- 地雷を開いたらゲームオーバー。地雷の位置が全部見える
- 地雷以外の 71 マスを全部開いたらクリア

## メモ

### 盤を持たない

g05 では盤を 8×8 の二次元リストで持ちましたが、今回は**盤にあたる変数がありません**。
あるのは 3 つの集合だけです。

```python
mines = set()    # 地雷のあるマス
opened = set()   # 開いたマス
flags = set()    # 旗を立てたマス
```

マインスイーパのマスの状態は「地雷か」「開いたか」「旗か」の組み合わせで決まり、
それぞれ**当てはまるマスは少数**です。81 マスぶんの入れ物を用意して大半を空のまま持つより、
当てはまるものだけを集めたほうが、状態が素直に表せます。

集合を選んだ理由は 3 つあります。

- `(row, col) in mines` の判定が、要素数に関係なく一定の速さで終わる
- 順番も重複も無い。地雷の集まりに 1 番目・2 番目の区別は要らない
- `add()` / `remove()` がそのまま「開く」「旗を外す」になる

### 盤外を聞くのは無害、盤外を記録するのは有害

同じ「盤の外の座標」でも、扱いが 2 か所で違います。数え上げには範囲チェックがありません。

```python
def count_around(mines, row, col):
    return sum((row + dr, col + dc) in mines for dr, dc in DIRECTIONS)
```

`(-1, -1)` を聞かれても、集合は「入っていない」＝地雷でないと正しく答えます。
盤の外が自動的に 0 として扱われる。g05 で毎回書いた `0 <= r < SIZE and ...` が丸ごと消えました。

一方、連鎖して開く `open_cell()` には範囲チェックが要ります。

```python
if not (0 <= row < SIZE and 0 <= col < SIZE):
    return
```

外さずに書くと `(-1, -1)` が `opened` に**入ってしまい**、そこからさらに外へ広がっていきます。
**読むだけなら外は無害、書き込むなら外は有害。**
座標を問い合わせているのか記録しているのかで、必要な守りが変わります。

### 連鎖は再帰で書く

0 のマスを開いたら周りも開く。開いた先がまた 0 ならその周りも開く。
何段になるか事前に分からないので、for ループの入れ子では書けません。

```python
def open_cell(mines, opened, row, col):
    if not (0 <= row < SIZE and 0 <= col < SIZE):
        return
    if (row, col) in opened:
        return

    opened.add((row, col))

    if count_around(mines, row, col) > 0:
        return

    for dr, dc in DIRECTIONS:
        open_cell(mines, opened, row + dr, col + dc)
```

本体に入る前に 3 回引き返します。それぞれ無いとどうなるかがはっきりしています。

| 止め条件 | 無いとどうなるか |
|---|---|
| 盤の外 | 座標がどこまでも伸びて止まらない |
| もう開いている | 隣どうしが互いを呼び合って無限に往復する |
| 周りに地雷がある | 数字で止まらず盤全体が開いてしまう |

肝は `opened.add()` の**位置**です。再帰呼び出しより前に書くことで、
`opened` が「もう来た」の目印を兼ねます。後ろに書くと、印が付く前に隣から呼び返されて止まりません。

**再帰で状態を持ち回るときは、印を付けてから進む。**

なお、広がるのは `count_around() == 0` のマスからだけです。
周りに地雷が無いと確認済みのマスの隣なので、広げた先が地雷であることはありえません。
**再帰の条件そのものが安全を保証している**ので、`open_cell()` に「地雷なら開かない」は要りません。

### 初手安全は、判定ではなく順番で作る

最初の一手で地雷を踏まないようにするのに、「踏んだらやり直し」は書いていません。
**地雷を置く時刻をずらした**だけです。

```python
if not mines:
    mines = place_mines(MINE_COUNT, around(row, col))
```

`main()` の始めでは `mines = set()`（空）にしておき、最初の入力を受け取ってから、
そのマスと周り 8 マスを避けて配置します。避ける範囲を 3×3 にしているのは、
初手が必ず 0 のマスになり、**連鎖でまとまった面積が開く**ようにするためです。
1 マスだけ避けると、初手が `８` で身動きの取れないゲームが生まれます。

`if not mines:` は「まだ空集合なら」の意味で、g05 の「空リストは偽」と同じ使い方です。
`started = True` のような旗変数を 1 個減らせます。
**状態がすでにデータに現れているなら、それを見にいく。**

### 旗は当たり外れを判定しない

`flags` はクリア判定に一切関わりません。

```python
def is_clear(opened):
    return len(opened) == SIZE * SIZE - MINE_COUNT
```

旗はプレイヤーのメモであって、正解を知っている必要がないからです。
「旗を全部正しく立てたらクリア」にすると、地雷の場所を知っているプログラム側と
メモを突き合わせることになり、**開けていないのにクリアになる**抜け道ができます。
開いたマスの数だけで判定すれば、その心配がありません。

### 表示は「見せてよい情報」を引数で受け取る

```python
def board_text(mines, opened, flags, reveal=False):
```

`board_text()` は地雷の場所を知っていますが、`reveal` が True のときしか描きません。
終局の 2 か所だけが `reveal=True` を渡します。

`board_text(mines, opened, flags, True)` でも動きますが、
呼び出しを見ただけでは `True` が何の True か分からなくなります。
**真偽値を渡すときは名前を書く**（キーワード引数）と、後から読めます。

条件の順番も仕様そのものです。

```python
if reveal and (row, col) in mines:
    cells.append(MINE)
elif (row, col) in opened:
    cells.append(NUMBERS[count_around(mines, row, col)])
elif (row, col) in flags:
    cells.append(FLAG)
else:
    cells.append(HIDDEN)
```

地雷を最優先に置くことで、`reveal` が立った瞬間に他を飛び越えて `＊` になります。

### 文字列を「添字で引く表」として使う

```python
NUMBERS = "・１２３４５６７８"
```

`NUMBERS[3]` が `"３"`、`NUMBERS[0]` が `"・"`。周りの地雷の数をそのまま添字にできるので、
`if count == 1: ... elif count == 2: ...` を 8 個書かずに済みます。
辞書でも書けますが、**添字が 0 から連番のときは文字列やリストのほうが短い**。

表示に全角文字だけを使っているのは幅を揃えるためです。
`■ ・ １ Ｆ ＊` はどれも半角 2 文字ぶんなので、ヘッダーの `a b c` と桁が合います。
半角の `1` を 1 つ混ぜた瞬間に盤面が崩れます。

### `f3` と `fd3` を長さで見分ける

`f` は旗の印であると同時に、**列の名前でもあります**。3 文字なら旗、2 文字なら通常の入力、
と長さで分けて両立させています。

```python
flagging = len(text) == 3 and text[0] == "f"
pos = parse_move(text[1:] if flagging else text)
```

`text[1:] if flagging else text` は条件式で、「旗なら先頭の f を落としたもの、
そうでなければそのまま」を 1 行で書いたものです。
おかげで `parse_move()` は**旗のことを何も知らないまま**使い回せています。
入力の解釈を 1 か所に閉じ込めるための切り分けです。
