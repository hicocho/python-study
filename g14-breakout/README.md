# g14 ブロック崩し

パドルでボールを打ち返して、40 個のブロックを全部壊す CLI ゲームです。
パドルの端に当てるほど横に飛び、8 個壊すごとにボールが速くなります。ボールは 3 つ。

g15 ピンボールとの 2 段階の連作で、この g14 が「ベクトルと物理の土台」、g15 が「斜めの壁と重力」です。

今回の主題は 3 つです。

- **演算子オーバーロード** — `Vec` に `__add__` `__mul__` `__neg__` `__abs__` `__iter__` を書いて、`ball + vel * dt` と数式のまま書けるようにする
- **`float` の物理** — 位置と速度を小数で持ち、描くときだけ `round()` でマスに丸める。壁は「速度の成分を反転」
- **`time.monotonic` と dt** — 1 コマではなく「経った時間ぶん」進める。速さは「1 秒あたりのマス数」

## 仕様

- 盤は 40 × 20 マス。ブロックは 2〜5 行目に横 4 マスのものが 10 個ずつ、計 40 個
- ボールの速さは 16 マス/秒から始まり、8 個壊すごとに 2 ずつ上がる（最大 26）
- **パドル**：当たった位置で跳ね返る向きが変わる。中央なら真上、端なら横 1.2 : 上 1 の角度
- **ブロック**：1 コマ前のマスと比べて、行が変わっていれば上下から（`vy` 反転）、列が変わっていれば横から（`vx` 反転）
- **壁**：左右と天井だけ。下に落ちるとボールが 1 つ減り、パドルの上から打ち直し
- 描き直しとキー読みは 0.05 秒ごと。ボールは実際に経った時間ぶん進む（上限 0.05 秒）

## メモ

### `__add__` — `ball + vel` と書けるようにする

```python
@dataclass(frozen=True)
class Vec:
    x: float
    y: float

    def __add__(self, other):
        return Vec(self.x + other.x, self.y + other.y)
```

`a + b` と書くと、Python は `a.__add__(b)` を呼びます。`__init__` や `__str__`（g11）と同じ「二重下線の特別なメソッド」で、
**演算子に自分の型の意味を教える**のがこの回の主題。`Vec(1, 2) + Vec(3, 4)` を `Vec(x=4, y=6)` にできるので、
物理の式が `ball = ball + vel * dt` と**教科書のまま**書けます。

| 書き方 | 呼ばれるもの |
|---|---|
| `a + b` | `__add__` |
| `a - b` | `__sub__` |
| `a * 2` | `__mul__` |
| `2 * a` | `__rmul__`（右側にいるとき） |
| `-a` | `__neg__` |
| `abs(a)` | `__abs__` |
| `x, y = a` | `__iter__` |

### `__rmul__ = __mul__` — 関数を値として名前を付け直す

`2 * v` のとき Python はまず `int` の `__mul__` を試し、だめなら `v.__rmul__(2)` を呼びます。
かけ算は順番を変えても同じなので、**同じ関数にもう 1 つ名前を付ける**だけで済みます。
g10 の `key=lambda`、g13 の `dealer_play(hand, draw)` に続く「関数は値」の 3 つ目の顔です。

### `__abs__` と `__iter__`

`abs(v)` でベクトルの長さが出るようにしました（`math.hypot`）。`normalized()` が `v * (speed / abs(v))` と 1 行で書けます。
`__iter__` は `for` や `x, y = v` で使われるもので、`yield` を 2 回書くだけ（g10 のジェネレータ）。
`bounce()` の `vx, vy = vel` はこれのおかげです。

### 壁は「成分の反転」、パドルは「向きの付け直し」

```python
    if not 0 <= nxt.x <= WIDTH - 1:
        vx = -vx
```

壁にぶつかったら、その向きの速度だけ符号を変える。上下の壁なら `vy`、左右なら `vx`。これが反射のすべてです。

パドルは違います。当たった位置で角度を決め直したいので、`Vec(offset * 1.2, -1)` と**向きを作ってから `normalized()` で速さを合わせる**。
速さを変えずに向きだけ変える、が `normalized(v, abs(vel))` の意味です。

### ブロックは「1 コマ前のマス」と比べる

```python
    prev = block_cell(ball)
    if prev[0] != cell[0]:      # 行が変わった ＝ 上下から
        vy = -vy
    if prev[1] != cell[1]:      # 列が変わった ＝ 横から
        vx = -vx
```

どの面に当たったかを角度から計算しようとすると難しい。**いまのマスと 1 コマ前のマスを比べる**だけで、
行が変わっていれば上下、列が変わっていれば横、両方なら角、と分かります。ブロックの横幅が 4 マスなので、
列は `x // BLOCK_WIDTH` で出します。

### 壁はいつでも最後に見る

最初はパドルに当たった回は壁を見ていませんでした。するとパドルの左端で跳ね返ったボールが、
そのまま左の壁を突き抜けて `x = -0.79` に。当たり判定を「パドル → ブロック → 壁」の `if`-`else` にしていたためです。

```python
        self.vel = bounce(self.ball, self.vel, dt)          # 壁はいつでも最後に見る
        self.ball = self.ball + self.vel * dt
```

パドルやブロックで向きを変えた**あとの速度で**もう一度壁を見る。30 局の自動プレイで盤の外に出ないことを確かめました。

### `time.monotonic` と dt — 1 コマではなく「経った時間」で進める

ステップ 3 までは「1 コマに 0.8 マス」と決めていました。すると描画が重い環境ではゲームが遅くなり、軽い環境では速くなる。

```python
            now = time.monotonic()
            dt = min(now - last, MAX_DT)
            last = now
            ...
            self.ball = self.ball + self.vel * dt
```

速さを「1 秒に 16 マス」と決め、実際に経った秒数 `dt` をかけて進めます。`time.monotonic()` は
時計合わせで戻ったりしない「経過時間用の時計」（g13 の `perf_counter` の仲間）。

`min(..., MAX_DT)` は**上限**です。ウィンドウを切り替えて戻ってきたとき、1 秒ぶんを一度に進めるとボールが
壁を突き抜けます。0.05 秒より長い `dt` は 0.05 に切り詰めて、その代わりゲームが少しゆっくりになる。
**突き抜けるより遅くなるほうがまし**という判断です。

### `round()` は描くときだけ

```python
    bx, by = round(ball.x), round(ball.y)
```

位置は小数のまま持ち、**文字にする瞬間だけ**マスに丸めます。計算のたびに丸めると誤差が積み重なって、
同じ角度で打ったのに違う場所に着く。ブラウザ版はこの丸めすらせず、% で置くので小数のまま見えます。

### `Game.update(dt)` — 時間を受け取るメソッド

g09 の `tick()` は「1 ティック進める」でしたが、今回は `update(dt)` と**秒数を受け取ります**。
CLI 版は `read_key` の待ち時間から、ブラウザ版は `asyncio.sleep` の前後から `dt` を測って渡す。
`Game` は時計を持たず、外から渡された時間ぶんだけ動く——だから同じ `dt` を渡せば同じ軌道になり、
CLI 版とブラウザ版を 5 局 × 4000 コマ突き合わせて一致しました。
