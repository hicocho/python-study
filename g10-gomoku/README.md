# g10 五目ならべ

15 × 15 の碁盤に黒と白が交互に石を置き、たて・よこ・ななめのどれかに
先に 5 個そろえたら勝ちの CLI ゲームです。白は CPU が打ちます。

盤と方向探索は g05 のオセロと同じ形ですが、今回は**数え方をジェネレータにする**のが山です。
`yield` を覚えると「石を1つずつ流す関数」が書けて、勝敗判定も CPU の評価も同じ関数で済みます。

今回の主題は 3 つです。

- **ジェネレータ `yield`** — 必要な分しか作らない。`break` した時点で計算も止まる
- **`lambda` と `key=`** — 関数を値として渡し、`max` に「何で比べるか」を教える
- **`defaultdict` と辞書内包表記** — 石の「形」を数えて点数にする

## 仕様

- 盤は 15 × 15。5 個そろえたら勝ち（6 個以上並んでも勝ち。長連の禁止は無し）
- 黒が先手。禁じ手（三三・四四）は無し
- 盤が埋まったら引き分け
- **CPU** は 1 手先だけを見る。読みはしないが、置いたときにできる石の**形**を点数にする
  - `(並ぶ数, 空いている端の数)` の組で形を表し、`SHAPE_POINTS` で点数を引く
  - 両端をふさがれた形は辞書に無い ＝ 0 点。伸ばしても 5 にならないので価値がない
  - 自分が置いたときの点数と、**相手がそこに置いたときの点数**を両方見る（後者が守り）
  - 考えるのは石から 2 マス以内の空きマスだけ（225 → 20〜100 マス）
- **待った**は 2 手戻る（CPU の手と自分の手）。何回でも、開始局面まで戻せる
- ハイスコアのようなファイルは持たない（1 局で完結するため）

## メモ

### `yield` — 途中で止まる関数

```python
def stones_from(board, row, col, dr, dc):
    """(row, col) の隣から (dr, dc) 方向へ、盤の端まで石を1つずつ返す。"""
    r = row + dr
    c = col + dc

    while 0 <= r < SIZE and 0 <= c < SIZE:
        yield board[r][c]
        r += dr
        c += dc
```

`return` は関数を終わらせますが、`yield` は**値を1つ渡してその場で一時停止**し、
次に求められたら止まった行から再開します。こういう関数を**ジェネレータ**と呼びます。

大事なのは、呼ぶ側が途中でやめられることです。

```python
    for stone in stones_from(board, row, col, dr, dc):
        if stone != player:
            break
        count += 1
```

リストを返す関数だったら、**端までの 14 マスぶんを全部作ってから** 1〜2 個見て捨てることになります。
ジェネレータなら `break` した時点で計算そのものが止まる。
この関数は CPU が 1 手につき 8 回 × 候補の数だけ呼ぶので、ここが効いてきます。

g06 の `sum(1 for ...)` で書いたジェネレータ式が、`def` の形になったものです。

### 方向は 4 本でいい

```python
DIRECTIONS = [(0, 1), (1, 0), (1, 1), (1, -1)]
```

オセロ（g05）は「挟む」ゲームなので 8 方向すべてを別々に見る必要がありました。
五目は「線」なので、→ の裏は ← と決まっています。

```python
    forward = count_same(board, row, col, dr, dc, player)
    backward = count_same(board, row, col, -dr, -dc, player)
    return 1 + forward + backward, ends
```

`-dr, -dc` と符号を反転して同じ関数をもう一度呼ぶだけ。**探索の本数が半分になります。**

```
・ ● ● ● ● ● ・
    ←2─ ↑ ─2→     backward=2, forward=2, 自分1 → 5
        いま置いた石
```

### `key=` に渡すのは値ではなく関数

```python
    return max(cells, key=lambda move: score_move(board, move, player))
```

`max` に `key=` を渡すと、**各要素を `key` に通した結果で比べて、元の要素のほうを返します**。
ここでは座標を点数に変換して比べ、いちばん点数が高かった**座標**が返ってきます。

`score_move` をそのまま渡せないのは、`key=` に渡す関数が**引数を1つだけ**取る決まりだからです。
`lambda` で包むと `board` と `player` を外側から捕まえたまま、`move` だけ受け取る関数になります。

`sorted(key=...)`、`min(key=...)`、`filter`、`map`、そして `defaultdict(int)` の `int` も
**関数を値として渡す**同じ形です。

### 「長さ」ではなく「形」

ステップ3 の CPU は線の長さしか見ていませんでした。五目では**同じ 3 でも価値が全然違います**。

```
・ ● ● ● ・     (3, 2)  両端が空いている → 次に 4 になり、止められなくなる
○ ● ● ● ・     (3, 1)  片端だけ空き    → まだ止められる
○ ● ● ● ○     (3, 0)  両端ふさがり     → 何個並んでも一生 5 にならない
```

そこで `line_shape()` が `(並ぶ数, 空いている端の数)` の**タプル**を返し、
`SHAPE_POINTS` がそのタプルをキーにして点数を引きます（タプルをキーにする辞書は g05 でも使いました）。

```python
SHAPE_POINTS = {
    (4, 2): 10000,   # 両端が空いた4。もう止めようがない
    (4, 1): 1000,    # 片端が空いた4。次の手で勝てる
    (3, 2): 500,     # 両端が空いた3。放っておくと (4, 2) になる
    ...
}
```

**`(3, 0)` や `(4, 0)` が書かれていない**のがポイントです。`.get(shape, 0)` が 0 を返すので、
「詰んだ形には一切点を与えない」が辞書の**書かないこと**で表現できています。

この 1 点だけで、ステップ3 の CPU に **20 戦 20 勝**しました。

### `defaultdict(int)` — 同じ形が 2 本できることがある

```python
    counts = defaultdict(int)              # 無いキーは 0 から始まる辞書

    board[row][col] = player
    for shape in shapes(board, row, col, player):
        counts[shape] += 1
    board[row][col] = EMPTY
```

ふつうの辞書だと初回で `KeyError` になるので `if shape not in counts: counts[shape] = 0` が要ります。
`defaultdict(int)` は**知らないキーを聞かれたら `int()`（= 0）を作ってから答える**辞書で、その行が消えます。

数える理由は `{(4, 1): 2}`——「片端が空いた 4 が十字に 2 本」があるからです。
相手はどちらか片方しか止められないので実質勝ちですが、
長さの `max` を取っていたステップ3 では 1 本の 4 と同じ点数でした。

```python
    for (length, ends), n in counts.items():
```

`items()` は `(キー, 値)` を返しますが、キー自身がタプルなので**カッコを入れ子にしてほどいて**います。

### 攻めと守りを、同じ関数を色だけ変えて呼ぶ

```python
    mine = shape_score(shape_counts(board, row, col, player))
    yours = shape_score(shape_counts(board, row, col, opponent(player)))

    return mine * 10 + yours * 9
```

`yours` は「**そのマスに相手が置いたらどれだけ嬉しいか**」です。
相手が喜ぶマスを先に取る ＝ 守り。

守りのロジックを別に書かず、**引数の色を変えてもう一度呼ぶだけ**にしてあるので、
`SHAPE_POINTS` を 1 か所直せば攻めと守りの両方に効きます。
`10` と `9` の差は「同じ価値なら攻める」を整数だけで表したものです。

### 盤はコピーせず、置いて戻す

```python
    board[row][col] = player                # 置いてみて
    ...
    board[row][col] = EMPTY                 # 元に戻す
```

候補が 100 マスあれば 100 回コピーすることになるので、
**同じ盤に一時的に書いて、必ず消す**やり方にしています。
置く行と戻す行は必ずセットで書きます。戻し忘れると盤が壊れます。

`Game.undo()` も同じ考え方です。

```python
        row, col = self.history.pop()
        self.board[row][col] = EMPTY
```

`pop()` は**末尾を取り除いてその値を返す**メソッド。積んだ順と逆に出てくるので、
盤を保存しなくても「待った」が書けます。

### 手番は覚えずに、手数から計算する

```python
        # 黒が先手なので、残った手数が偶数なら次は黒
        self.player = BLACK if len(self.history) % 2 == 0 else WHITE
```

`undo` では手番も巻き戻す必要がありますが、履歴と手番を**別々に覚えていると 2 つがずれます**。
黒が先手と決まっている以上、手番は履歴の長さから必ず求まる。

g09 で「負け方が 2 通りでも `result` に状態を増やさない」と書いたのと同じ判断です。
**同じ事実を 2 か所に持たない。**

```python
def winning_line(board, row, col, player):
    """(row, col) の石で 5 個以上そろっているなら、その石の座標を並べて返す。"""
    ...
    return []
```

呼ぶ側は今までと同じ `if` で書けます——**空リストは `False`、中身があれば `True`** だからです。
情報を増やしても使い勝手は変わらないまま、`◆` のハイライトが無料で付いてきました。

### `class Game` に入れたもの／入れなかったもの

| 入れた | 入れなかった |
|---|---|
| `board` `player` `history` `winning` `result` | `input` と `print`（`ask_move` と `main` に残した） |
| `place` `undo` `cpu_move` | 盤の読み方（`winning_line`、`score_move` などの関数） |

`Game` が知っているのは**1 局の状態と、その進め方**だけです。`input` を一切呼ばないので、
ブラウザ版では `ask_move` の代わりに「クリックされたマス」を `place()` に渡すだけで済みました。

### ブラウザ版：共有部分は手で写さず、`ast` で切り出す

g09 では `main.py` から**行の範囲**を文字列で切り出して `game.py` を組み立てましたが、
今回は共有する部分が飛び飛び（`board_text` と `parse_move` を挟んで前後に散っている）なので、
`ast` で関数・クラスの位置を拾って原文の行をそのまま連結しました。

```python
    for node in tree.body:
        if isinstance(node, ast.FunctionDef):
            out[node.name] = text_of(node)
        elif isinstance(node, ast.ClassDef):
            drop = [b for b in node.body
                    if isinstance(b, ast.FunctionDef) and b.name in DROP_METHODS]
            out[node.name] = text_of(node, drop)   # render() だけ落とす
```

**名前で指定できる**ので、行番号がずれても壊れません。
`class Game` から `render()` だけを抜くのも、行の範囲を引き算するだけで済みます。

### ブラウザを開く前に、3 つに分けて確かめる

g09 で決めた通り、確認したいものを分けて潰しました。

| 確かめるもの | やり方 | 結果 |
|---|---|---|
| ルール | `winning_line()` を総当たり実装と 200 局突き合わせ | 勝ち筋 200 本すべて一致 |
| 待った | ランダムな局面で `place` → `undo` し、盤・手番・履歴・結果を比較 | 50 回すべて完全一致 |
| CPU の強さ | ステップ4 の CPU 対 ステップ3 の CPU を 20 局 | 20 戦 20 勝 |
| 移植 | 同じ乱数の種で CLI 版と `docs/g10/game.py` を自動対局 | 5 局とも同じ棋譜 |
| 結線 | Playwright でクリック・待った・勝ち筋の表示 | エラーなし |

**同じ種を渡すと同じ棋譜になる**ので、移植のずれは 1 手目で分かります。
`random` を使う CPU でも、乱数の種を固定すれば再現できる——これが自動で確かめられた理由です。

そして `import` 漏れは、ブラウザを開く前に `ast` で捕まえました。

```
未定義の名前: ['defaultdict', 'product', 'random']
```

g09 では `import random` の抜けを実機の `NameError` で見つけています。
共有部分は機械が写しても、**ヘッダ（import 群）は手で書くので必ず漏れる**。
`ast` で「読まれているのに定義も import もされていない名前」を洗うチェックは、
そのまま次の課題でも使えます。

### 碁盤の線は 1 枚の背景で引く

石は 225 個の `<div>` ですが、**線はマスに引いていません**。
`#board::before` を 1 枚かぶせて、繰り返しのグラデーションで引いています。

```css
  #board::before {
    inset: calc(100% / 30);          /* マスの半分ぶん内側＝いちばん外の交点まで */
    pointer-events: none;
    background:
      repeating-linear-gradient(to right, var(--wood-line) 0 1px, transparent 1px calc(100% / 14)),
      repeating-linear-gradient(to bottom, var(--wood-line) 0 1px, transparent 1px calc(100% / 14));
  }
```

マスごとに線を引くと**交点で二重になり、盤の端で半分はみ出します**。
1 枚にしてしまえば「いちばん外の交点から内側だけ」を `inset` で言えます（マスの半分 ＝ `100% / 30`）。
線は 14 本ぶんの間隔で繰り返すので `100% / 14` です。

`pointer-events: none` を忘れると、この 1 枚がクリックを全部吸って**盤が反応しなくなります**。
