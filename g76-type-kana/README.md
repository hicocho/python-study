[g75](../g75-type-keys/) の続き。打つものが「キーの並び」から**ことば**になる。「さくら」を `sakura` と打つ。

みじかい ことば → ながい ことば（ん・っ・きゃ・ー）→ ぶん、と段階を踏む。

## 今回の主題

**綴りのゆれを「いま居られる状態」の集合で受ける。**

`n` を打った時点では「ん が終わった」のか「nn の途中」なのかは決められない。次のキーで決まる。
だから**両方の状態を持っておく**。1 つのキーで、ある状態は次の単位へ進み、別の状態は打ちかけが伸びる。
どの状態も残らなければミス。

```python
        moved: set[tuple[int, str]] = set()
        for i, partial in self.states:
            trying = partial + char
            for spelling in spellings(self.units, i):
                if spelling == trying:
                    moved.add((i + 1, ""))          # この単位が終わった
                elif spelling.startswith(trying):
                    moved.add((i, trying))          # まだ途中
        if moved:
            self.states = moved                     # 居られる状態が 1 つでもあれば「合った」
```

これはオートマトン（NFA）そのもの。状態を 1 つに決めようとすると `n` の扱いで詰まるが、
**集合で持てば決めなくてよい**。

**1. かな → 単位 → 綴りの候補**

```python
ROMAJI = {"し": ("shi", "si"), "つ": ("tsu", "tu"), "きゃ": ("kya",), "じゃ": ("ja", "zya", "jya"), ...}

def spellings(units, i):
    if unit == "っ":   # 次の綴りの最初の子音を 1 つ重ねる（きって = kitte）
        return doubled + ("xtu", "ltu", "xtsu", "ltsu")
    if unit == "ん":   # 次が子音（な行・や行を除く）なら n 1 つでよい。母音・な・や の前、最後、空白の前は nn
        return (("n",) if lone else ()) + ("nn", "xn")
```

っ と ん は**次の単位を見て**綴りが決まる。表に書けないので関数にした。

**2. カタカナをひらがなに — `re.sub` に関数を渡す**

```python
def hiragana(text: str) -> str:
    return re.sub(r"[ァ-ヶ]", lambda m: chr(ord(m.group()) - 0x60), text)
```

見つかった字ごとに「どう置き換えるか」を計算できる。カタカナはひらがなの 0x60 あと。
判定はひらがなに寄せ、**表示は元の字のまま**（「ラーメン」はカタカナで見せる）。

**3. おすすめの綴りは、打ったゆれに合わせて変わる — `str.removeprefix`**

```python
    def hint(self) -> str:
        i, partial = self.best()
        rest = self.favorite(i, partial).removeprefix(partial)
        return rest + "".join(spellings(self.units, j)[0] for j in range(i + 1, len(self.units)))
```

「しんぶん」を `si` と打ったら、残りは `nbunn`。`sh` には戻さない。

## 遊び方

```
 段階 2/3  ながい ことば   打った 12  ミス 0  正確さ 100%

   おちゃ ラーメン けんこう しんぶん にんじん
   ocha ra-menn kenkou shinbunn ninjinn
   次は  k  →  右手 中指
   （キーボードの絵は g75 と同じ）
```

- 上のことばをローマ字で打つ。**自分の綴りで打ってかまわない**
- 違えば赤く光って、正しいキーを押すまで進まない
- ことばの間の空白は親指。文の「。」は `.`、「、」は `,`
- 正確さ 95% 以上で次の段階へ

## 仕様

- ローマ字の表は 123 項目（五十音・濁音・半濁音・拗音・小書き・ふぁ・てぃ・ー・、。）
- 段階 3 つ：みじかい ことば 30 語から 5 つ／ながい ことば 30 語（カタカナ含む）から 5 つ／ぶん 10 から 2 つ
- ん の決まり：次が子音（な行・や行を除く）なら `n` 1 つでも可。母音・な行・や行の前、最後、**空白や記号の前**は `nn`
- っ の決まり：次の子音を重ねる。`xtu` `ltu` でも可
- `--check` が見るもの：表の字が全部 JIS の表にあるか、70 語すべてローマ字にできるか、
  **6 語の綴りぜんぶ（`itertools.product` で作った 36 通りなど）を受けるか**、`na` を んあ と読まないか、
  おすすめが打ったゆれに合わせて変わるか、g75 の練習の決まりぜんぶ

## メモ

- **状態を 1 つに決めない。** `n` のあとに `n` が来るか `k` が来るかで ん の綴りが変わる。
  「決めない」ために集合で持つ。これで ん も っ も特別扱いの `if` が要らなくなった
- **受け付ける綴りぜんぶを検査で作る。** 単位ごとの候補の直積（`product`）をつないで、
  そのすべてを打って通ることを見る。「しんかんせん」は 36 通り
- **空白の前の ん を `n` 1 つで通してしまっていた。** 「次の綴りが子音で始まる」に空白が入っていた。
  IME では通るが練習では `nn` にしたいので、`isalpha()` で絞った
- **判定用に寄せた字を、そのまま見せていた。** カタカナのことばがひらがなで出た。
  判定はひらがな、表示は元の字、と分ける（`units` と `shown`）

## ブラウザ版の 3D 化（2026-09-19）

CLI 版は変えていない。ブラウザの `game.py` の末尾に、g75〜g77 共通の「3D のキーボードと手」の部分を足した（3 つの `game.py` に同じ文が入っている）。
判定・`keyboard_view()` の表・音の名前は 1 文字も変えていない。**表を読んで Three.js に写すだけ。**

- **Three.js のキーボード**：JIS 配列のキー 48 個を箱で並べる。上面は `CanvasTexture` に字を描いた絵、側面は指の色。
  f と j には突起。影は `DirectionalLight` の `castShadow` で落とす
- **手**：指先の球 10 個（手のひらは付けたが、キーを隠すのでやめた）。ホームポジションに置き、`keyboard_view()` で `next` になったキーの指だけ
  キーの上へ動く（毎コマ目標へ 22% ずつ寄せる）
- **押すと沈む**：`gsap.fromTo(mesh.position, {y:-0.18}, {y:0, ease:"elastic.out"})`。間違えると赤く光り、カメラが少し揺れて寄る
- **音は Tone.js**：`PolySynth` を人が触った処理（`keydown`）の中で 1 回だけ作る。**指ごとに音の高さが違う**
  （左小指 C4 → 右小指 E5、親指 G3 の五音音階）。間違えると E2+F2 の濁った 2 音。
  Tone.js が無いときは従来の wav に戻る（`kb_sound()` が False を返す）
- 描画は 30 fps の `asyncio` のループ。各課題は `kb_extra` に「毎コマの処理」を足す
- **ことばの板が奥から迫る（g76 だけ）**：いま打つことばを板（`PlaneGeometry` + `CanvasTexture`）に描き、
  キーの奥から手前の帯へ流す。着くまでの時間は「1.2 秒 + 残りのローマ字 × 0.55 秒」。
  着くと赤くなって揺れる（**判定は変わらない**。急かすだけ）。打ち終わると板は上へ飛び去り、次のことばが奥から来る。
  Python が持つのは「何番目のことばか」「いつ出たか」だけ。ことばの区切りは `units` の空白で数える
