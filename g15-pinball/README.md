# g15 ピンボール

右のレーンから打ち出して、バンパーに当てて得点を稼ぐ CLI ピンボールです。
重力で落ちてくるボールを、`z` `x` のフリッパーで打ち返します。ボールは 3 つ。

g14 ブロック崩しとの 2 段階の連作で、g14 が「ベクトルと物理の土台」、この g15 が「斜めの壁・重力・回転」です。

今回の主題は 3 つです。

- **`math` の三角関数** — `sin` `cos` `radians` でフリッパーを回す。`Vec.rotated()` は回転行列そのもの
- **内積を `__matmul__`（`@`）で** — 「壁のどちら側か」「離れていく向きか」「線分のどのあたりか」が全部内積で書ける
- **法線での反射** — `v - 2 (v · n) n`。斜めの壁もフリッパーも、この 1 行で跳ね返る

インストールせずに遊べます → **https://hicocho.github.io/python-study/g15/**

ソースは [`docs/g15/game.py`](../docs/g15/game.py)。定数 16 個と `Vec` / `Segment` / `Bumper` / `Flipper` の 4 クラス、
`reflect()` / `hit_segment()` / `hit_bumper()` / `make_walls()` / `make_bumpers()` / `make_flippers()`、
そして `class Game` を **1 文字も変えずに**持ってきています（`ast` で切り出して文字列比較で確認済み）。

持ってこなかったのは `raster()` / `field_text()` と `raw_mode()` / `read_key()` / `main()`、それに `Game.render()` だけ。
違うのは**入口と出口**で、

- 入口：`select` で待つ生キー入力 → `asyncio` の時計とキーイベント（ボタンも）
- 出口：文字の盤 → **SVG**。壁は `<line>`、バンパーは `<circle>`、フリッパーとボールは毎コマ座標を書き換える。
  CLI 版が `/ \ | -` の 4 文字で近似していた斜めの壁が、本当の線になる

## 仕様

- 盤は 32 × 26 マス。重力は 30 マス/秒²、ボールの半径 0.4 マス
- 右のレーン（x 29〜31）から 40〜46 マス/秒で打ち出す。天井の右角が斜めで、左へ流れる
- **バンパー** 5 個（半径 1.5）。当たると 100 点、少し強く弾き返し、0.25 秒光る
- **フリッパー** は左右 1 本ずつ。押すと 0.18 秒だけ上がり、上がっている最中に当たると 22 マス/秒ぶん強く打ち出す
- 壁で跳ね返るたびに速さが 0.9 倍（減衰）。最高速 48 マス/秒
- 物理は 1 コマ（0.04 秒）を 4 回に刻んで計算する。フリッパーの間から落ちるとボールが 1 つ減る
- レーンに戻ってきて止まったら、もう一度打ち出せる

## メモ

### `@` — 内積を演算子にする

```python
    def __matmul__(self, other):
        return self.x * other.x + self.y * other.y
```

`a @ b` は行列のかけ算用に用意された演算子ですが、自分の型では好きな意味を与えられます。
ベクトルの内積にすると、物理の式がそのまま書けます。

| 使いどころ | 式 |
|---|---|
| 壁のどちら側か | `(pos - seg.a) @ n` の符号 |
| 壁へ向かっているか | `vel @ normal < 0` |
| 線分のどのあたりか | `((p - a) @ ab) / (ab @ ab)` |
| 反射 | `vel - normal * (2 * (vel @ normal))` |

内積が「同じ向きなら正、直角なら 0、逆向きなら負」だと分かっていれば、この 4 つは全部同じ道具です。

### 反射は「法線に直角な成分だけ反転」

g14 の壁は水平か垂直だったので `vx = -vx` で済みました。斜めの壁では、速度を**壁に沿う成分**と**壁に直角な成分**に分けて、
直角な成分だけ反転します。それが `v - 2 (v · n) n`。

```python
def reflect(vel, normal):
    return vel - normal * (2 * (vel @ normal))
```

`(vel @ normal)` が直角な成分の大きさ、それを 2 回引くと反転になる。水平な壁（`normal = (0, -1)`）に入れると
`vy = -vy` に戻るので、g14 はこの特殊な場合だったと分かります。

### 法線は `perp()` — 90 度回す

```python
    def perp(self):
        return Vec(-self.y, self.x)
```

線分の向き `b - a` を 90 度回すと壁に直角なベクトルになり、`normalized()` で長さ 1 にすれば法線です。
`Vec(-y, x)` が「90 度回す」であることは、`rotated(radians(90))` に `cos 90 = 0, sin 90 = 1` を入れると出てきます。

### `rotated()` — 三角関数で回す

```python
    def rotated(self, radians):
        c, s = math.cos(radians), math.sin(radians)
        return Vec(self.x * c - self.y * s, self.x * s + self.y * c)
```

フリッパーは「軸から長さ 4 のベクトルを、角度ぶん回した先」が先端です。`Vec(4, 0).rotated(angle)`。
`math` の三角関数は**ラジアン**を受け取るので、`radians(30)` で度から直します。
画面の y は下向きなので、正の角度で時計回り。左のフリッパーは休んでいるとき 30°（右下）、上げると −25°（右上）。

### 速いボールは壁を「飛び越える」

最初は「壁に触れているか」だけを見ていました。すると重力で加速したボールが、1 コマで壁の向こう側へ抜けてしまう
（1 コマに 1.7 マス動くのに、半径は 0.4）。

```python
    side_prev = (prev - seg.a) @ n
    side_now = (pos - seg.a) @ n
    if side_prev * side_now < 0:                            # 符号が変わった ＝ 線をまたいだ
```

**1 コマ前と今で壁のどちら側にいるか**を内積の符号で見て、変わっていたら「またいだ」。
またいだ点が線分の範囲内かも `((cross - a) @ ab) / (ab @ ab)` で確かめます。
60 × 3000 コマの落下で 1 度も抜けなくなりました。

### 1 コマを 4 回に刻む — サブステップ

```python
        h = dt / SUBSTEPS
        for _ in range(SUBSTEPS):
            self.step(h)
```

またぎ判定があっても、1 コマで 2 本の壁を続けて越えるような角では取りこぼします。
物理だけを細かく刻めば、描画は 0.04 秒に 1 回のまま、当たり判定は 0.01 秒ごとになります。
**描く頻度と計算する頻度は別**——g14 の「描く間隔と動く速さを分けた」の続きです。

### 減衰と上限

跳ね返るたびに 0.9 倍（`RESTITUTION`）。これが無いとレーンの底で永遠に跳ね続けて、ボールが止まりません
（最初の検証で 25 局中 3 局しか終わらなかった原因の 1 つ）。逆にバンパーとフリッパーは速さを**足す**ので、
`MAX_SPEED` で上限を切っています。

### レーンから上がった球を左へ流す

打ち出しの速さは 30〜38 にしていましたが、`v² / 2g` で計算すると最高点が y = 9 あたりで、天井の斜め（y ≤ 6）に届かない。
届かないと真下に落ちてレーンの底で跳ね続けます。**40 以上なら必ず届く**ので 40〜46 に直しました。
物理の式で「どこまで上がるか」が先に分かるのは、`float` で持っている利点です。

### `Flipper` だけ `frozen` ではない

`Vec` と `Segment` は変えられない（`frozen=True`）のに、`Flipper` と `Bumper` は普通のクラスです。
フリッパーは「上がっている残り時間」、バンパーは「光っている残り時間」を持ち、時間で変わるから。
**変わらないものは `frozen`、変わるものは普通のクラス**——g11 の `Card`（固定）と `Hand`（増える）の使い分けと同じです。
`Flipper.segment` は `@property` で、読むたびに角度から線分を作ります。

### ブラウザ版は SVG

文字の盤では斜めの壁を `/` と `\` で近似していましたが、ブラウザでは `<svg viewBox="0 0 32 26">` に
**CLI 版と同じ座標のまま** `<line>` を引けます。`Segment` の `a` `b` をそのまま `x1 y1 x2 y2` に入れるだけ。
ボールは `<circle r="0.4">` で、半径まで CLI 版の定数と同じです。
