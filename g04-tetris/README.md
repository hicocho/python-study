# g04 テトリス

矢印キーで操作する CLI のテトリスです。ミノは 0.8 秒ごとに勝手に 1 マス落ち、
横 1 列がそろうと消えます。積み上がって次のミノを出せなくなったら終わりです。

## ブラウザ版

インストールせずに遊べます → **https://hicocho.github.io/python-study/g04/**

ソースは [`docs/g04/game.py`](../docs/g04/game.py)。盤面まわりの 5 つの関数
（`can_place` / `place` / `rotate` / `clear_lines` / `spawn`）は CLI 版から
1 文字も変えずに持ってきています。違うのは**入口と出口**だけで、
キーの読み取りと画面の描き方が入れ替わっています。

## 遊び方（ターミナル）

```bash
python3 main.py
```

| キー | 動き |
|---|---|
| ← → | 左右に動かす |
| ↑ | 時計回りに 90 度まわす |
| ↓ | 1 マス落とす |
| スペース | 一番下まで一気に落とす |
| q | やめる |

```
|..........|
|..........|
|....#.....|
|...###....|
|..........|
|..........|
|.......##.|
|#####.####|
+----------+
スコア 300   消した列 2
← → 移動 / ↑ 回転 / ↓ 落下 / スペース 一気に / q やめる
```

## 仕様

- 盤面は横 10 × 縦 20。ミノは 7 種類（I・O・T・S・Z・J・L）
- 落下は 0.8 秒に 1 マス（`FALL_SECONDS`）。キーを押しても落下のリズムは狂わない
- 壁・床・積んだブロックにぶつかる操作は、単に無視される
- 回転して置けない位置になる場合は回転しない（壁際でずらして回す「壁蹴り」は無し）
- 落ちられなくなったら固定。そろった列を消して、消した列数でスコアが入る
- スコアは同時に消した数で決まる（1 列 100 / 2 列 300 / 3 列 500 / 4 列 800）
- 新しいミノを初期位置に置けなくなったらゲームオーバー

## メモ

### 盤面は「確定したブロック」だけを持つ

このゲームで一番効いている設計です。落下中のミノは盤面に書き込まず、
`shape`・`x`・`y` の 3 つの変数だけで表しています。

```python
print(render(place(board, shape, x, y, name)))  # 表示のためだけ。board は無傷
board = place(board, shape, x, y, name)         # 受け取った瞬間、確定
```

`place()` は元の盤面を変えず、**書き込んだコピー**を返します。同じ関数なのに、
返り値を変数に代入するかどうかで「まだ動いている」と「もう固定された」が分かれます。

盤面に直接書き込む作りにすると、1 マス動かすたびに前の位置を消す処理が要ります。
どのマスが自分のミノだったかを別に覚えておかないと消せないので、
結局「動いているミノの位置」を持つことになります。それなら最初から持っておくほうが早い。

### `[[0] * WIDTH] * HEIGHT` は動かない

2 次元リストを作るときの罠です。

```python
>>> bad = [[0] * 3] * 2
>>> bad[0][0] = 1
>>> bad
[[1, 0, 0], [1, 0, 0]]    # 1 行しか変えていないのに両方変わった
```

`* 2` は行をコピーせず、**同じ 1 個のリストを 2 回並べる**だけだからです。
内包表記なら毎回 `[0] * WIDTH` を作り直すので、20 行が別々のリストになります。

```python
[[0] * WIDTH for _ in range(HEIGHT)]
```

同じ理由で、盤面のコピーも `board.copy()` では足りません（外側だけコピーされ、
行は共有されたまま）。`[row[:] for row in board]` と、行ごとにコピーします。

### 回転は「上下反転 → 転置」

```python
def rotate(shape):
    return [list(row) for row in zip(*reversed(shape))]
```

T ミノで追うとこうなります。

```
.#.        ###          #.
###   →    .#.    →     ##
           ↑上下逆      #.
                        ↑行と列を入れ替え
```

`zip(*rows)` の `*` は「リストの中身をバラバラの引数として渡す」印で、
`zip(rows[0], rows[1], ...)` と書いたのと同じです。結果はタプルで返るので
`list()` でリストに戻しています。4 回まわすと必ず元の形に戻ります。

### 消えた行を詰めるのではなく、残る行を集める

```python
kept = []
for row in board:
    if 0 in row:          # 1 マスでも空きがあれば、その行は残す
        kept.append(row)

cleared = HEIGHT - len(kept)
for _ in range(cleared):
    kept.insert(0, [0] * WIDTH)
```

埋まった行を消して上を下げていく書き方もできますが、消すたびにリストの長さが変わり、
添字がずれて厄介です。残す行だけを新しいリストに集めれば、途中の状態を考えずに済みます。
何行消えたかは高さの差（`HEIGHT - len(kept)`）で分かるので、数える変数も要りません。

### 矢印キーは 1 文字ではない

`input()` では矢印キーが取れません。← を押しても文字列には何も現れず、
行編集のカーソルが左に動くだけです。

端末は ← を押すと `ESC` `[` `D` という **3 文字**を送ってきます。
`input()` はこれを「カーソルを左へ」という命令として食べてしまいます。
なので `os.read()` で端末から直接読み、辞書で名前に翻訳しています。

```python
ARROWS = {"\x1b[A": "up", "\x1b[B": "down", "\x1b[C": "right", "\x1b[D": "left"}
return ARROWS.get(key, key)    # 表になければ、押された文字をそのまま返す
```

画面を消す `"\x1b[2J\x1b[H"` はこの逆向きで、こちらから端末に送る命令です
（`2J` = 画面を消す、`H` = カーソルを左上へ）。**ESC で始まる並びが端末との共通の合図**
になっている、と見ると両方が同じ話に見えてきます。

### モードの切り替えは、ゲームの始まりと終わりの仕事

端末は標準では「1 行たまるまでプログラムに渡さない」モードです。
`tty.setcbreak()` で「1 文字来たら即渡す」に切り替えます。

最初はキーを読む関数の中で切り替えて、読み終えたら戻していました。これだと
**盤面を描いている一瞬のあいだに押されたキーが行バッファに吸い込まれ、届かなくなります**。
自動落下を入れて描画と待機を往復し始めたところで表に出ました。

なのでゲームのあいだはずっと cbreak のままにして、`finally` で終了時に一度だけ戻します。

```python
saved = termios.tcgetattr(fd)
try:
    tty.setcbreak(fd)
    ...ゲーム本体...
finally:
    termios.tcsetattr(fd, termios.TCSADRAIN, saved)
```

`finally` は g01 の `except` と違い、**成功しても失敗しても必ず通る**ブロックです。
端末の設定を戻さずに終わると、そのあとのシェルで打った文字が見えなくなります。
Ctrl+C で止めても `finally` は通ります。

なお、より強い `tty.setraw()` は出力の改行処理まで止めてしまい、盤面が階段状に崩れます。
止めたいのは「Enter 待ち」と「文字の表示」だけなので `setcbreak` が正解です。

### 自動落下は「時間切れを ↓ とみなす」

`os.read()` は普通、キーが押されるまで待ち続けます。それでは勝手に落ちてくれません。
`select.select()` は**待つ時間に上限をつけて**、入力が来たかどうかだけを教えてくれます。

```python
key = read_key(max(next_fall - time.time(), 0))  # 次の落下時刻までの残り時間だけ待つ
if key is None:
    key = "down"                                 # 時間切れ＝自分で ↓ を押したことにする
```

自動落下のために新しい処理は 1 つも書いていません。落下・固定・ライン消去・次のミノ、
という流れはすでに `"down"` の枝にまとまっているので、**入口をひとつ増やしただけ**です。
