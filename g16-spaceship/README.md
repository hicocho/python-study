# g16 宇宙船

慣性で滑る宇宙船を矢印キーで操縦し、2 つの星の引力に引かれながら 5 つのリングを順にくぐる CLI タイムアタックです。
星にぶつかると船が壊れます。船は 3 機。

g16 → g17 → g18 の 3 段階の連作で、この g16 が「宇宙船と物理」、g17 が「小惑星と弾」、g18 が「ランキング」です。

今回の主題は 3 つです。

- **`complex` を 2 次元のベクトルとして使う** — `real` が x、`imag` が y。足し算・引き算・`abs()` が最初から付いている。g14 で自作した `Vec` を、Python 組み込みの型でやり直す
- **`cmath.rect` と `cmath.phase`** — 「長さと向き」から複素数を作る／複素数から向きを取る。回転は複素数のかけ算
- **`%` は小数でも使える** — 画面の端をループさせるのが 1 行

## 仕様

- 画面は 50 × 22 マス。端を越えると反対側から出てくる
- 何もしなくても速さが 3 秒で半分になる（宇宙だが、操縦しやすいように少し減速する）。最高速 30 マス/秒
- **星**は 2 つ（半径 2 と 2.5）。引力は距離の 2 乗に反比例、星の中に入るとその船は壊れる
- **リング**は 5 つ、決まった順にくぐる。中心から 1.5 マス以内に入ればくぐったことになる
- 全部くぐるとクリア、タイムが出る。3 機壊れると終わり
- 乱数を使っていないので、同じ操作をすれば同じ軌道になる

## メモ

### `complex` — Python に最初から入っている 2 次元ベクトル

```python
pos = complex(5, 11)        # real が x、imag が y
pos = pos + vel * dt        # 足し算・実数倍がそのまま使える
abs(vel)                    # 長さ
```

g14 では `__add__` や `__abs__` を自分で書いて `Vec` を作りました。**同じことが `complex` には最初から付いています**。
g14 の `Vec` は「演算子オーバーロードとは何か」を知るためのもの。知ったあとは、既にあるものを使えばよい。

| g14 の `Vec` | `complex` |
|---|---|
| `Vec(x, y)` | `complex(x, y)` |
| `v.x` `v.y` | `v.real` `v.imag` |
| `abs(v)` | `abs(v)` |
| `v.rotated(θ)` | `v * cmath.rect(1, θ)` |
| `normalized(v, s)` | `cmath.rect(s, cmath.phase(v))` |

### `cmath.rect(r, φ)` — 長さと向きから作る

```python
    def thrust(self):
        self.vel += cmath.rect(THRUST, self.heading)
```

「向いている方向へ 4 だけ速くする」が 1 行。`rect` は極座標（長さと角度）から直交座標への変換で、
`(r cos φ, r sin φ)` を自分で書く必要がありません。逆が `cmath.phase(v)` で、速度ベクトルの向きを角度で返します。

### 回転は複素数のかけ算

`complex(1, 0) * cmath.rect(1, π/2)` は `1j`——右向きを 90° 回すと下向き（画面の y は下向き）。
**長さ 1 の複素数をかけると、その角度ぶん回る**のが複素数の性質で、g15 で `sin` `cos` を並べて書いた回転行列と同じことです。

### 引力は `d * (G m / |d|³)`

```python
def gravity(pos, planets):
    total = 0j
    for planet in planets:
        d = planet.center - pos
        total += d * (G * planet.mass / abs(d) ** 3)
    return total
```

向きは `d / |d|`、強さは `G m / |d|²`。かけると `d · G m / |d|³`。`0j` から足していくのは `sum` の複素数版で、
星が何個あっても加速度の合計になります。

### `0.5 ** (dt / HALF_LIFE)` — 「3 秒で半分」を dt で書く

```python
def drag(vel, dt):
    return vel * 0.5 ** (dt / HALF_LIFE)
```

コマごとに `vel *= 0.99` と書くと、コマの長さが変わると減り方も変わります。
「`HALF_LIFE` 秒たったら半分」を `dt` の指数で書けば、`dt` がいくつでも同じ減り方になる——g14 の「速さは 1 秒あたり」の続きです。

### `%` で画面の端をループ

```python
def wrap(pos):
    return complex(pos.real % WIDTH, pos.imag % HEIGHT)
```

`-1 % 50` は `49`。Python の `%` は負の数でも 0 以上を返し、小数でも使えるので、右端を越えても左端を越えても 1 行で反対側に出ます。

### 8 方向の記号は `round(heading / (π/4)) % 8`

角度を 45° で割って四捨五入し、`% 8` で 0〜7 に収めて `">\\v/<\\^/"` から拾う。
`round` で「いちばん近い方向」、`%` で「1 周したら戻る」。

### `for ... else` — ぶつからなかったときだけ

ステップ 4 では、星にぶつかったときは `break`、ぶつからなかったときだけリングを見たい。`for` の `else` は
**`break` せずに回り終えたときだけ**走るので、旗の変数を置かずに書けます（g01 の `while`-`else` の `for` 版）。

### 自動操縦で「クリアできる設計か」を確かめる

引力を 250 にしていたときは、何もしないと 4 秒で星に落ち、自動操縦でも 1 回もクリアできませんでした。
90 に下げて、「次のリングへ向かう速度になるように向きを合わせて加速する」だけの自動操縦を書くと、20 回とも約 10 秒でクリア（船は 1 機失う）。
**ゲームが成立しているかは、人が遊ぶ前に機械で確かめられる**——g13 のロボットと同じ考え方です。
