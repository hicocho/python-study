# g75 タイピング1（キーボードと指）

ブラインドタッチの練習。画面に **JIS 配列のキーボード**を描き、次に押すキーと
**どの指で押すか**を出す。ホームポジション → 上の段 → 下の段 → 数字、と段階を踏む。
正確さ 95% 以上で次の段階へ。

**ブラウザ版**: https://hicocho.github.io/python-study/g75/

タイピング 3 段階の 1 つ目（**g75 キーボードと指** → g76 ローマ字で日本語 → g77 記録と苦手キー）。

```bash
python3 main.py            # 練習する（日本語入力はオフに）
python3 main.py --check    # 決まりを確かめる
python3 main.py --drill 2  # 段階 3 の練習文を見る
```

## 今回の主題

**絵を、まずデータにする。** キーボードは `(文字, 指, 段, 位置)` の表で持ち、
「いまどのキーが光るか」も表として組み立てる。端末はその表を色つきの字に、
ブラウザは同じ表を `<div>` に変える。**絵の中身は 1 か所で決まる。**

```python
def keyboard_view(game: Game) -> list[list[tuple[str, Finger, str]]]:
    """キーボードの「いまの見た目」を表にする。端末もブラウザもこれを描く。

    各キーは (文字, 指, 状態)。状態は "next" / "miss" / "home" / ""
    """
```

**1. JIS 配列と指 — `enum.Enum` と `dict` 内包**

```python
ROWS = (
    ("1234567890-^¥", 0.0),
    ("qwertyuiop@[", 1.5),
    ("asdfghjkl;:]", 2.0),
    ("zxcvbnm,./_", 2.5),
)

KEYS: dict[str, Key] = {
    char: Key(char, finger_of(column), row, column)
    for row, (chars, _) in enumerate(ROWS)
    for column, char in enumerate(chars)
} | {" ": Key(" ", Finger.THUMB, 4, 0)}
```

指は「段の中の位置」で決まる（左端から 小・薬・中・人・人・人・人・中・薬、右へはみ出したぶんは全部小指）。
段が違っても同じ位置なら同じ指、という規則をそのまま書いた。

**2. 練習文 — 種を固定した乱数**

```python
def drill(index: int, seed: int = 0) -> str:
    luck = random.Random(seed * 100 + index)
```

同じ段階・同じ回なら端末でもブラウザでも同じ文。新しいキーを 6 割、覚えたキーを 4 割。

**3. 時計を中で読まない — `obey(game, key, now)`**

```python
def obey(game: Game, key: str, now: float) -> None:
    """now は外から渡す。中で時計を読まないので、同じキー列と同じ時刻を与えれば
    端末でもブラウザでも同じ結果になる（検証で使う）。"""
```

速さは `statistics.fmean`（キーとキーの間隔の平均）から出す。

## 遊び方

```
 段階 1/4  ホームポジション   打った 12  ミス 1  正確さ 92%

   jjag lkjg kh;f ldgd s;gl ;dgs shkl shjh
                ^
   次は  j  →  右手 人さし指

   1 2 3 4 5 6 7 8 9 0 - ^ ¥
     q w e r t y u i o p @ [
      a s d f g h j k l ; : ]
        z x c v b n m , . / _
                 空白
```

- 文のとおりに打つ。**手元は見ない**。キーボードの絵で場所と指を確かめる
- 違えば**赤く光って、正しいキーを押すまで進まない**（ミスは数える）
- 打ち終わると成績（打鍵・ミス・正確さ・秒・1 分あたり・**ミスの多い指**）
- **正確さ 95% 以上**でリターン → 次の段階。届かなければ同じ段階を別の文で
- 端末は指ごとに 9 色、ホームポジションは下線。ブラウザも同じ色分け

## 仕様

- 段階 4 つ：ホームポジション（asdfghjkl;）→ 上の段（qwertyuiop）→ 下の段（zxcvbnm,./）→ 数字
- 1 回は 4 キー × 8 かたまり＝32 キー＋空白 7 つ。空白は親指で打つ
- 合格ライン `PASS = 0.95`。新しいキーの割合 `FRESH = 0.6`
- ブラウザは日本語入力がオンだと警告（`event.key == "Process"` で分かる）
- `--check` が見るもの：JIS の段のキー数 13/12/12/11、a〜z と 0〜9 が全部あり 9 本の指が全部使われる、
  段階に重なりが無い、練習文が習ったキーだけでできている、全部正しく打てば合格、
  間違えたら進まない、95% 未満なら同じ段階、見た目の表で光るキーがちょうど 1 つ

## メモ

- **絵を共有する代わりに、絵の「もと」を共有した。** これまで（g55〜g74）は `Screen` のドットを共有して
  画素の一致を検証した。キーボードには字が要るのでドット絵では読めない。`keyboard_view()` という
  「どのキーがどの状態か」の表を共有し、検証は**その表が 536 コマすべて一致**することで見る
- **時計は外から渡す。** `obey()` の中で `time.perf_counter()` を読むと、検証で同じ時刻を与えられない。
  「いま」を引数にした瞬間、端末とブラウザの結果が突き合わせられるようになった
- **切り出しは「定義」しか拾わない。** `KEYS[" "] = …` という代入文は共有部分に入らなかった。
  `{...} | {" ": ...}` と 1 つの式にまとめて解決。書き方を変えるだけで道具に合う
- **g73 のスマホ用 CSS（並べ替え）をそのまま持ってきたら崩れた。** `order` を付けた要素と付けていない要素が
  混ざると、付けていない方が先頭に来る。要素が変わったら並べ替えも書き直す
- 日本語入力がオンだと `event.key` が `"Process"` になって字が届かない。日本の環境ではまず起きるので、
  黙って無視せず警告を出す
